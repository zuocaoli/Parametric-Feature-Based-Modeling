# 第四个月第 2 周：事务与失败恢复

## 本周训练

- **承接与前置**：将[上周](../week01/README.md)的单命令组合为一个用户操作；区分延迟重算、隔离候选和事务提交。
- **目标**：能证明组合操作成功时只新增一条历史和一次通知；能区分非法命令与合法编辑后的计算失败。
- **独立练习**：以 A 的 length=120、width=`length/2`、area=`length*width` 为起点，组合修改 length=144、name="A2"；撤销后提交 length=144、segments=0 的坏组合，再提交原合法组合。
- **验收**：成功组合为 72/10368 且一次撤销恢复两项输入；坏组合保留原内容、历史和通知次数；修复后可继续提交。另推演 segments=1 导致除零时为何保留合法编辑。

## 66. 如何让一次用户操作包含多个命令，并作为一个整体撤销？

CompositeCommand 顺序执行一组子命令，Document 保存整个操作前后的快照，只追加一条历史。因此两个输入修改的一次 undo 同时恢复两个值，redo 恢复整组。本课支持一层组合，明确拒绝嵌套和空子命令；空组合不产生历史。

## 67. 一组命令执行到中途失败时，如何恢复操作前的状态？

在隔离候选模型中执行，第二个命令失败就丢弃候选；当前模型从未接受部分修改，历史位置和重做分支保持原状。比逐个逆操作回滚更容易提供完整恢复，但要复制模型。错误消息附带失败子命令序号，观察者不会收到候选模型的属性事件。

## 68. 如何让一组修改完成后只触发一次重算？

Document 为整组打开一个引擎批次，子命令只提交输入并收集脏节点，全部成功后关闭批次进行一轮拓扑重算。引擎每个受影响公式最多执行一次。失败候选不关闭批次、不计算，直接销毁；外部只在成功提交并完成重算后收到一个文档事件。批次只负责延迟计算，隔离候选才提供事务语义。

## 69. 用户直接修改的值和重算产生的值，分别应如何参与历史记录？

用户动作产生一条命令记录，重算写回是该动作的派生结果，不递归进入历史。内存快照保留计算缓存便于恢复失败前的诊断数据，但缓存不是新的用户输入。撤销/重做重建图后统一计算，不通过重复压入“修改结果值”命令实现。

## 70. 如何区分命令执行失败和命令成功但模型重算失败，并制定恢复规则？

非法属性值、只读目标或子命令失败返回执行错误，不提交。合法输入导致除零则是成功编辑：保留输入及历史，width 标 Failed、area 标 Blocked，value 不交出缓存；用户可修复输入或 undo。计算状态在事件和引擎报告中查询，不把“模型存在错误”误写成“命令已经回滚”。

## 代码与运行

自定义命令返回错误或抛出标准/非标准异常时，Document 都返回 EngineError 并丢弃候选，当前模型和历史保持不变，且不通知。标准异常保留 what()；非标准异常给出明确诊断。组合命令同时保留失败子命令序号。可用先修改候选再抛错的命令观察失败保护，再执行重做与继续编辑核对恢复。

[组合与事务](document.cpp)、[接口](document.cppm)。自包含复制第一周模块；文档是唯一对外修改入口，底层属性通知仅供内部协调。快照恢复重建 AST/图/订阅而不预先求值，普通组合保持增量计算；undo/redo 进行一次全公式重算。单线程、回调只读，不能跨提交保存模型引用。
