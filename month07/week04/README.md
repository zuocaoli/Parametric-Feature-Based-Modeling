# 第七个月第 4 周：单位与参数化文档、持久化和数据交换

## 本周训练

- **承接与前置**：[上一周](../week03/README.md)已能推演带单位公式与依赖重算；复习第四月命令/事务和第六月语义快照。
- **目标**：完整说明一次单位输入如何进入文档，以及保存、加载、撤销和交换如何保持物理意义。
- **独立练习**：创建 length=`1000 mm`、width=`length/2 + 10 mm`、area=`length*width` 的矩形并保存；将 length 改为 `2 m` 后撤销，再仅把长度显示改成 in，保存并重新打开。
- **验收**：撤销后恢复 `1 m / 0.51 m / 0.51 m²`；改显示不重算、不改变几何，但因文档显示配置持久化而 modified=true；保存后重新打开规范值、公式、显示配置相同，历史清空且 modified=false。

本周采用文档状态表完成独立推演，无需构建。以下 `CAD_DOCUMENT 3` 是拟议的新格式；第五月和第六月现有程序仍只支持版本 2。总体设计及课程边界见[单位系统计划](../../unit-plan/plan.md)。

## 136. 参数化文档应该持有什么单位信息，各模块如何协作？

文档持有对象与属性、正式公式、稳定绑定、输入/显示配置，以及公式需要的自定义单位定义快照。内置单位可由固定版本注册表提供；文档必须记录版本，不能依赖另一台机器上的“最新定义”。

单位核心提供换算与运算服务，文档负责决定何时提交修改。一个完整请求沿用第六月 `query/preview/apply` 的思路：

```text
UI / 外部调用
  → 解析带单位输入并冻结输入上下文
  → 生成类型明确的操作请求，附预期文档版本
  → preview：在候选文档中校验、改值、重算，返回差异和诊断
  → apply：检查版本，在相同定义与规则下执行事务
  → 提交规范值、公式状态和历史
  → 一次最终通知
  → UI 格式化 / 几何适配器换算
```

preview 不改变正式文档；预览之后文档值、单位定义或相关配置发生变化，应使旧请求的版本检查失败，重新预览。提交内容使用已解析的工程量，不能再按当前 UI 单位重新解释裸数。

外部请求同样通过类型和范围校验。例如长度输入 `{value: 2, unit: "m"}` 可写入 Length；传入 `kg` 被拒绝。外部调用不能通过直接写 double 绕开 UI 已经遵守的单位规则。

## 137. 单位相关修改如何参与命令、撤销、通知和未保存判断？

| 用户操作 | 命令应保存 | 重算与事件 |
|---|---|---|
| 输入 `2 m` 修改长度 | 旧/新规范工程量及属性键 | 重算下游，发布模型事件 |
| 替换带单位公式 | 旧/新公式原文、属性绑定和单位绑定 | 更新依赖并重算 |
| 显示 mm → in | 旧/新显示配置 | 发布格式事件，数值重算次数为零 |
| 调整默认输入单位 | 旧/新输入配置 | 影响新编辑，已提交模型不重算 |
| 迁移自定义单位定义 | 旧/新定义版本及受影响绑定 | 显式重绑定、重算并允许整体撤销 |

命令保存权威输入，派生结果可重新计算。错误状态沿用前几个月的恢复策略；撤销时也用当时绑定的定义恢复含义，不能查当前全局同名单位。

本课把文档输入/显示配置作为持久内容，所以仅改变显示也会 modified=true，并产生可撤销配置命令。它与“几何模型是否改变”是两个判定：修改文档元数据不要求重算几何。

未保存判断比较规范输入、公式及绑定、必要单位定义和文档配置与保存基准；排除派生数值、求值状态、格式缓存、选择、草稿和历史。只改变显示不能污染数值；用户主动改写等价公式原文仍属于文档编辑，沿用第六月的文本比较约定。

## 138. 保存和加载怎样恢复单位语义，哪些数据不能只保存显示文本？

拟议版本 3 明确记录规范单位契约及表达式语言版本。数据分工如下：

| 保存内容 | 作用 |
|---|---|
| 格式版本、规范单位方案 ID、属性模式版本 | 明确数值和类型的解释方式 |
| 对象 ID、未绑定属性的规范值及必要类型信息 | 恢复权威输入；固定类型可从受版本约束的属性模式取得 |
| 公式原文、属性引用映射、单位字面量到稳定单位 ID/版本的绑定 | 保证名称、默认设置变化后语义仍相同 |
| 内置注册表版本、自定义单位定义及依赖定义闭包 | 在另一环境恢复相同换算规则 |
| 文档输入/显示方案、属性覆盖、精度 | 恢复编辑和显示习惯 |

公式的单位绑定可按源文本范围记录；加载时校验范围与语法树对应，不能盲目信任旧偏移。受影响的自定义定义需完整保存；缺少定义时拒绝加载并说明原因，不能按“无单位”继续。

不把 `39.3701 in` 这样的舍入显示字符串当作唯一数值来源。规范浮点数以足够的往返精度保存；依赖图、类型缓存、计算结果和错误状态从权威数据重建。已经失败但绑定合法的模型仍可保存，加载后重现 Failed/Blocked；没有可靠缓存时不伪造上次有效几何。

加载顺序为：检查版本及定义 → 在候选文档创建对象和属性 → 绑定公式并检查类型/循环 → 建图并重算 → 全部结构校验成功后替换正式文档。未知版本、损坏定义或绑定错误不影响当前文档；合法公式的运行时失败可成为加载后状态。保存文件提交成功后才更新保存基准。

## 139. 如何迁移旧文件，并与几何内核、导入导出和算法交换数据？

旧版课程的裸长度按 mm、面积按 mm² 解释。版本 2 到新设计的升级器必须从旧格式/属性模式取到这些约定，分别乘 `10⁻³` 和 `10⁻⁶`。不能把原 `1000` 直接当成 `1000 m`，也不能对所有数值统一缩放；布尔值、计数和比例不参与长度换算。

旧公式没有单位，迁移需要保留原计算含义：

| 旧公式及目标 | 可证明等价的新公式 |
|---|---|
| width=`length/2` | `length/2`，2 保留为比例 |
| width=`length+10` | `length+10 mm` |
| width=`50` | `50 mm` |
| area=`length*width` | `length*width`，按量纲推导为面积 |

只对经过规则证明的模式自动重写。旧公式可能把不同量纲当数字混用，例如 `area = length + width`；不能凭目标类型猜测它的物理含义。遇到歧义应生成迁移报告、保留源文件并拒绝完成替换，待用户明确改写。迁移后的值需在原单位下与旧模型比对，确认成功后另存新版本。

导入文件有单位声明时按声明换算；缺少单位时，由格式契约或明确的导入选项决定并记录，不猜测物体大小。导出时明确目标单位、坐标及容差；若格式支持混合单位或局部变换，需要逐层解释。先验证格式的实际能力，再制定适配，不能假定所有格式都像长度字段一样处理。

核心 `1 m` 经毫米几何接口得到 `1000 mm`，再导出为英寸得到约 `39.37007874 in`；重导入应恢复约 `1 m`。法向方向不缩放，线性容差随长度单位换算，面积/体积量分别使用平方/立方比例。

进入 Boost.Units 算法前，适配器校验类型及温度类别，再转换到所选 Boost 单位系统。返回值重新包装成受检运行时工程量；角度、能量/力矩等语义还需要双方一致的领域契约。

## 140. 如何用一条完整案例验证单位、表达式和文档始终一致？

固定矩形公式 width=`length/2 + 10 mm`、area=`length*width`，依次记录规范值、显示值、依赖执行次数、历史位置和 modified 状态。

| 步骤 | 规范 length / width / area | 预期行为 |
|---|---|---|
| 创建 length=`1000 mm` 并绑定两式 | `1 m / 0.51 m / 0.51 m²` | 保存为基准，modified=false |
| 将 length 改成 `2 m` | `2 m / 1.01 m / 2.02 m²` | 一个命令，两个派生属性各算一次，modified=true |
| 撤销 | `1 m / 0.51 m / 0.51 m²` | 回到保存内容，modified=false |
| 仅切长度显示为 in，面积仍显示 mm² | 数值保持原样 | length≈`39.3701 in`，width≈`20.0787 in`；重算次数零，modified=true |
| 保存后重新打开 | 数值、公式及配置相同 | 重建结果，历史清空，modified=false |
| 尝试将 length 改成 `2 kg` | 保持原值 | 输入错误，无新历史 |
| 尝试将 width 公式改成 `length + 1 kg` | 保持旧公式和依赖 | 绑定错误，无新历史 |

另用第三周的 ratio 案例验证合法修改引发除零、下游阻塞、撤销或修复后的恢复。损坏文件、未知格式版本、缺少单位定义以及带单位导出再导入也需要独立覆盖。

验收按三种标准判断：显示切换要求规范值原样不动；纯存储往返要求权威浮点输入和绑定恢复一致；数值换算与重新求值按带量纲的绝对容差加相对容差比较。不要用格式化文本相等代替物理意义相等。

## 月底成果与下一阶段

能够从一次 `2 m` 输入，追踪解析、类型检查、公式求值、依赖排序、事务、通知和持久化的全过程；也能指出显示切换、非法输入和合法计算失败各自走哪条路径。

后续进入几何与约束求解时，还需要把求解器变量尺度、残差量纲和容差统一到明确接口。单位正确是前提，但无法单独解决大型坐标精度、病态约束和几何鲁棒性；这些是下一阶段的学习动机。
