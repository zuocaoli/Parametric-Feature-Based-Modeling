# 第 2 月第 1 周：结构自由度分析

## 本周训练

- **承接与前置**：承接可运行求解器和每行方程的参数依赖。
- **唯一新增功能**：用方程—参数二部图最大匹配估计结构自由度。
- **学习方式**：先推导本周必要公式，再阅读模块实现，最后改变输入并核对结果。

## 1. 方程与参数怎样组成二部图？

一侧为方程行，一侧为参数；若方程定义可能使用该参数，就连接一条边。本实现对引用实体递归收集依赖，属于保守的结构依赖，不取某次差分的偶然非零。

## 2. 静态依赖关系为何优于某次 Jacobian 的偶然非零值？

某个导数可能仅因当前位置恰好为零；使用它删边会使结构分析随构型抖动。静态依赖保留潜在关联，但也可能过度估计独立关系。

## 3. 增广路径怎样增加匹配数量？

尝试给新方程分配参数；参数已被占用时，递归为原方程寻找替代参数。每次搜索标记访问参数防止循环，成功就增加一个匹配。

## 4. 未匹配参数能说明什么？

参数数减匹配数是结构自由度估计，未匹配参数是某种匹配结果下的代表。它们不等于所有可动坐标，也不构成唯一的自由参数选择。

## 5. 结构自由度为什么不一定等于实际自由度？

匹配只看能否连接，不能判断方程之间的几何相关性。删除宽度后再重复添加一条水平约束，可使结构估计回到零，但真实宽度仍能变化。

## 独立练习与验收

输出完整矩形、删宽度矩形及删宽度再加重复水平约束的匹配数，解释最后一种结果的局限。

structure 测试验证三种构型的结构自由度分别为 0、1、0。本周 SolveReport 的 dof 尚为 −1，只有 structuralDof 可用。

实现入口：[src/diagnostics.cpp](src/diagnostics.cpp)；验证入口：[核心测试](tests/core_tests.cpp)。

```bash
cmake --preset default
cmake --build --preset default
ctest --preset default --no-tests=error
ctest --preset default -R "^(structure)$" --no-tests=error
./build/console-demo --headless
./build/demo
```

依赖版本、Qt 可选配置、运行参数与 clangd 设置见 [tools/README.md](tools/README.md)。
