# 第 2 月第 3 周：冗余约束定位

## 本周训练

- **承接与前置**：承接数值秩与局部自由度。
- **唯一新增功能**：把相容系统中的相关方程定位到用户约束 ID。
- **学习方式**：先推导本周必要公式，再阅读模块实现，最后改变输入并核对结果。

## 1. 方程数量多为什么不一定意味着冲突？

两条相同尺寸提供相同信息，仍然可以同时满足。只有它们要求的数值不相容时才形成矛盾，不能按行数大于参数数直接判冲突。

## 2. 行相关与约束冗余有什么关系？

逐组加入约束行，若新增秩小于新增行数，说明该约束含有一阶相关方程。只在求解已经收敛的相容构型上将其作为冗余诊断。

## 3. 多方程约束怎样作为整体判断？

重合或固定的多行作为一个组参与秩比较，报告用户约束 ID。部分行相关时也返回该 ID，但这不表示整条约束可以安全删除。

## 4. 存在多个等价冗余集合时怎样稳定输出？

先加入圆弧内部方程，再按用户约束添加顺序累积，优先保留已有独立关系。因此新增重复尺寸稳定指向新 ID，不承诺唯一数学冗余集合。

## 5. 为什么还要检查残差相容性？

行相关只描述导数，不能证明目标相容。本周只在全部残差已满足时运行冗余报告；保留全部方程继续求解，不自动删除组合约束。

## 独立练习与验收

给全约束矩形重复添加宽度，再重复固定锚点；删除高度后观察冗余与欠约束同时出现。

redundancy 测试精确返回新增宽度 ID，验证固定约束两行归一 ID，并验证 Redundant 状态下 dof 仍能为 1。

实现入口：[src/diagnostics.cpp](src/diagnostics.cpp)；验证入口：[核心测试](tests/core_tests.cpp)。

```bash
cmake --preset default
cmake --build --preset default
ctest --preset default --no-tests=error
ctest --preset default -R "^(redundancy)$" --no-tests=error
./build/console-demo --headless
./build/demo
```

依赖版本、Qt 可选配置、运行参数与 clangd 设置见 [tools/README.md](tools/README.md)。
