# 第 3 月第 1 周：尺寸驱动更新

## 本周训练

- **承接与前置**：承接成功构型保存、状态诊断和失败回退。
- **唯一新增功能**：通过修改尺寸目标值驱动模型连续更新。
- **学习方式**：先推导本周必要公式，再阅读模块实现，最后改变输入并核对结果。

## 1. 尺寸目标值与几何参数有什么区别？

目标值属于约束，表示希望达到的长度、角度或半径；几何参数是求解变量。setConstraintValue() 只修改目标，之后 solve() 才更新构型。

## 2. 修改尺寸后为什么沿用上次成功构型？

相邻尺寸通常具有邻近解，上次成功构型提供稳定的局部起点。参数数量变化时使用当前模型输入作为初值；同尺寸参数的手动改写不会覆盖已保存的成功初值。

## 3. 失败更新怎样避免污染当前几何？

只在收敛后保存几何，失败保留上一成功参数。尺寸目标仍保留用户提交的新值，报告指出失败；调用方可以修正目标再重解。

## 4. 连续小幅修改为何通常比大幅跳变稳定？

小变化更符合线性化的局部前提，大变化可能跨越退化区或进入别的吸引域。小步测试是连续性证据，不是任意输入的全局保证。

## 5. 相切和角度分支怎样保持明确？

圆圆相切保存内外切枚举，线圆相切保存侧别；有向角使用周期残差。显式分支与上次解共同限制局部更新，但奇异点附近仍可能失败。

## 独立练习与验收

每步增加 0.5 mm 矩形宽度；给两个相切圆连续修改半径，观察圆心距离和原分支。

dimensions 测试覆盖连续尺寸更新、非法值拒绝、失败时几何保持，以及相切圆的小步半径变化。Qt 面板从本周提供宽度编辑。

实现入口：[src/model.cpp](src/model.cpp)；验证入口：[核心测试](tests/core_tests.cpp)。

```bash
cmake --preset default
cmake --build --preset default
ctest --preset default --no-tests=error
ctest --preset default -R "^(dimensions)$" --no-tests=error
./build/console-demo --headless
./build/demo
```

依赖版本、Qt 可选配置、运行参数与 clangd 设置见 [tools/README.md](tools/README.md)。
