## 背景

问题: 文档模型侧对单位系统的封装与装配分析。

与姊妹篇《单位系统App层组成》(模块清单式总览)的分工: 本篇下钻一层, 回答"同一个带单位属性在 C++ / Python / 表达式三条通道下, 值、单位、格式如何被校验与流转", 以及 Application / Document 如何装配引擎。

## 结论: 三通道写值语义分化是核心机制

App 层单位系统 = 属性封装(PropertyUnits) + 表达式封装(Expression) + 装配(Application / Document)。Base 层提供引擎, App 层决定文档模型如何**持有、校验、流转**单位。核心机制是同一个属性有三条写值通道, 单位行为存在差异；这里描述源码行为，不推断历史动机:

```
C++ 直写 setValue(double)        → 零检查, 约定内部单位
Python 赋值 setPyObject(PyObj)   → 严格: 单位不匹配抛 UnitsMismatchError; 无量纲绕过
表达式赋值 setPathValue(any)     → 宽松: 非无量纲则 _Unit 随值自适应
```

## 一、属性封装: PropertyQuantity 三通道

状态(`src/App/PropertyUnits.h:101-102`): 值存 `PropertyFloat` 的 `_dValue`(double, **内部单位**), 另持 `Base::Unit _Unit` 与 `Base::QuantityFormat _Format`。读值组装: `getQuantityValue()`(`PropertyUnits.cpp:49`)、`getPyObject()` 返回 `QuantityPy`(`:61`)、`getPathValue()` 返回带单位 `Quantity`(`:131-135`, 供表达式比较)。

| 通道 | 入口 | 单位行为 |
| --- | --- | --- |
| C++ 直写 | `setValue(double)`(`PropertyUnits.h:67`) | **无任何单位检查**, 约定调用方给内部单位 |
| Python 赋值 | `setPyObject(PyObject*)`(`PropertyUnits.cpp:92`) | 传 `UnitPy` → 直接换 `_Unit`(带 aboutToSetValue/hasSetValue 通知, `:95-101`);<br>否则 `createQuantityFromPy`(`:66`): 字符串 → `Quantity::parse`(`:67-69`), float/int → 按当前 `_Unit` 解释(`:71-76`), `QuantityPy` → 透传(`:77-80`), 其他 → 抛 `Base::TypeError`(`:81-86`);<br>**无量纲值绕过检查直写**(`:106-109`); 有量纲但与 `_Unit` 不符 → 抛 `Base::UnitsMismatchError("Not matching Unit!")`(`:112-114`) |
| 表达式/引用赋值 | `setPathValue(path, any)`(`:120`) | `App::anyToQuantity(value)`(`:122`); **非无量纲则 `_Unit = q.getUnit()`——量纲随非无量纲结果更新**(`:124-126`), 与 setPyObject 的严格检查形成关键差异 |

表达式通道的写入点: `src/App/PropertyExpressionEngine.cpp:377`(绑定表达式求值后 `isAnyEqual(value, myProp->getPathValue(var))` 不相等才 `setPathValue`)与 `:756`(批量重算赋值)——**表达式引擎是 setPathValue 的唯一调用方**。

### 约束子类 PropertyQuantityConstraint

- 只在 `setPyObject` 中**静默裁剪**(clip)越界值到上下界(`PropertyUnits.cpp:184-197`), C++ / 表达式通道不受约束。
- `getMinimum/getMaximum/getStepSize` 返回原始 `Constraints{LowerBound, UpperBound, StepSize}`(`:160-182`), App 侧不做单位换算。
- 内置标准约束(`PropertyUnits.cpp:39-41`):
  - `LengthStandard = {0.0, max, 1.0}` — 长度类禁负(下限 0)
  - `AngleStandard = {-360, 360, 1.0}` — 角度 ±360°。**内部角度单位是度(°)**: 各 schema 的 Angle 换算因子均为 1.0(如 `UnitsSchemasData.h:57` `{ "Angle", {{0, "°", 1.0}}}`), 边界即 ±360°
- `PropertyLength::enableNegative()`(`PropertyUnits.cpp:526-529`)是禁负约束的动态开关: 开 → 卸掉 `LengthStandard` 指针, 关 → 挂上。

### 编辑器解耦

`getEditorName()` 返回字符串 `"Gui::PropertyEditor::PropertyUnitItem"`(约束类为 `"Gui::PropertyEditor::PropertyUnitConstraintItem"`, `PropertyUnits.cpp:56/150`)。App 层**不 include Gui**, 属性编辑器按名字查找条目类——文档模型与 UI 的依赖倒置点。

### 类型即单位

59 个具体属性类的构造差异仅在于 `setUnit(Base::Unit::X)`: `PropertyAngle` → `Unit::Angle` + `AngleStandard`(`:243-247`)、`PropertyArea` → `Unit::Area` + `LengthStandard`(`:255-259`)、`PropertyLength` → `Unit::Length` + 默认禁负(`:520-524`)、`PropertySpeed` → `Unit::Velocity`(`:669-672`)。

## 二、表达式封装: UnitExpression 家族

- `UnitExpression`(`src/App/ExpressionParser.h:79`, 实现 `Expression.cpp:1232`): 成员 `quantity + unitStr`, `_getPyValue` 缓存 `pyFromQuantity(quantity)`(`:1286`), `simplify()` 折叠成 `NumberExpression`(`:1277`)。派生家族 `NumberExpression/OperatorExpression/FunctionExpression/VariableExpression`(`ExpressionParser.h:138/190/297/457`)全部带单位。
- `anyToQuantity`(`Expression.cpp:520-537`): bool/int/long/float/double → **无量纲** Quantity; 字符串不支持(必须先处理字符串, 见 `:605` 注释)——表达式字符串在更早环节已解析成 Quantity 节点。
- `isAnyEqual`(`Expression.cpp:598`): 字符串优先比较(`:605-620`), Quantity 走类型分支(`:622` 起)——绑定赋值前先比较, 相等则跳过写, 避免无谓的 aboutToSetValue/hasSetValue 通知。
- 单位一致性错误有两个来源: `Base::Quantity` 算术运算(不匹配抛 `UnitsMismatchError`, `src/Base/Quantity.cpp:132`)与 `PropertyQuantity::setPyObject` 的显式检查; **表达式通道不做严格检查, 而是以值带单位覆盖 `_Unit`**。
- `UnitExpression::init()` 在 `Application::initApplication` 调用(`Application.cpp:2353`)。

## 三、装配: Application 与 Document

- **`FreeCAD.Units` Python 模块**(`Application.cpp:528-542`): `UnitsModuleDef` 挂到主模块, `addType` 注册 `QuantityPy`/`UnitPy`——Base 提供、App 装配。
- **生命周期**: `cleanupUnits()`(`Application.h:980`, 实现 `Application.cpp:1984`)析构时清空 `FreeCAD.Units` 属性, 由 `Application.cpp:2040` 调用; `UnitsMismatchError` 注册进 Python(`:2109`、`:2402`)。
- **全局状态初始化**(`Application.cpp:3034-3039`): 读 `User parameter:BaseApp/Preferences/Units` 的 `UserSchema/Decimals/FracInch` → `UnitsApi::setSchema/setDecimals/setDenominator`。
- **文档级单位制**: `Document::UnitSystem` 属性(`Document.h:171`, 定义 `Document.cpp:992`): 枚举由 `UnitsApi::getDescriptions()` 填充(`:995`), 默认取用户参数 `UserSchema`(`:999`)。**App 层只存储, 全部消费方在 Gui**: `Gui/Application.cpp:1320`、`Gui/MainWindow.cpp:264-265/288`(新文档继承当前用户单位制)、`Gui/Document.cpp:3201`(`setUserSchema`)、`DlgProjectInformationImp.cpp:102`(项目信息对话框)、`DlgSettingsGeneral.cpp:199-246`(偏好页含 `IgnoreProjectSchema` 开关, 决定 `UnitsApi::setSchema` 用文档值还是全局值)。

## 四、两条端到端数据流

**Python 赋值**:

```
obj.Length = "1.5 in"
  → setPyObject → createQuantityFromPy → Quantity::parse("1.5 in")
  → 归一化为 Quantity(38.1, Unit::Length)
  → 与属性长度量纲相同 → _dValue = 38.1（内部mm）
obj.Length = "1.5 mm" → 相符 → _dValue = 1.5
obj.Length = 1.5      → float 按当前 _Unit 构造 → 单位相符 → _dValue = 1.5
obj.Length = "1.5"    → 字符串解析为无量纲 Quantity → 走无量纲旁路 → _dValue = 1.5
```

**表达式赋值**:

```
属性绑定 Spreadsheet.A1 (=25.4 mm)
  → ExpressionEngine 求值 → NumberExpression(Quantity(25.4, mm)) → getValueAsAny
  → isAnyEqual(现值) 不相等 → PropertyExpressionEngine.cpp:377 → setPathValue(path, any)
  → anyToQuantity → 非无量纲 → _Unit 取结果的长度量纲 → 存内部值25.4
  → 量纲原本相同则不变；mm/in/m等显示单位另由schema决定
```

## 五、设计要点

- **值、单位、格式三分离**: `_dValue`(内部单位 double)/`_Unit`/`_Format` 独立存储, 换算只在显示与解析边界做(归 `Base::UnitsApi`), 属性本身不算。
- **通道行为需要明确记录**: 脚本通道有量纲检查和无量纲旁路，表达式通道可更新量纲，C++通道约定内部值。这是已核验的实现事实，不据此断言历史动机；教学实现是否采用相同策略需单独设计。
- **装配与引擎分离**: 引擎全在 Base(见系列 01), App 只做类型化封装与模块装配; 编辑器经字符串名字解耦, App 无 Gui 依赖。
- **约束裁剪静默且仅限 Python 通道**: 越界值被 clip 到边界而不是报错, 脚本与 C++ 语义不一致, 消费方需知。
