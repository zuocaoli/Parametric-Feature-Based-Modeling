# 单位系统·第一月第 1 周：工程量模型与单位换算

## 本周训练

- **承接与前置**：[文档与属性系统·第四月末](../../../文档与属性系统/month04/week04/README.md)已有属性、公式、重算和事务；但属性的 `unit` 仍是显示字符串，数值使用 `double`，尚不能拒绝长度加面积。
- **目标**：设计 `Quantity`、`Dimension` 和 `UnitRegistry`，说明一个工程量从输入单位变成规范值的过程。
- **独立练习**：把矩形的 `length = 1000 mm`、`width = 50 cm` 转成规范值，求面积；再分别判断 `length + width`、`length + area`、`length / width`。
- **验收**：规范长度为 `1 m`、`0.5 m`，面积为 `0.5 m²`；三次运算分别得到 `1.5 m`、量纲错误和无量纲比例 `2`。能解释为什么显示成 `500000 mm²` 不改变面积。

本月是设计与机制课程，使用数据表和执行轨迹完成推演；接口名称表示拟议设计。学习从本 README 开始，无需构建，案例的初始状态均在本周给出。课程范围见[单位系统索引](../../README.md)。

## 121. 数值、单位、量纲和工程量类型分别表示什么？

`1000 mm` 包含数值 `1000` 和单位 `mm`；`mm`、`m` 都表示长度量纲，但换算比例不同。工程量是数值与物理含义的整体，规范化后可以表示为“`1`，长度，规范单位米”。

| 概念 | 本课程设计 | 矩形案例 |
|---|---|---|
| `Dimension` | 七个 SI 基本量纲的整数指数，顺序为长度、质量、时间、电流、温度、物质的量、发光强度 | 长度 `(1,0,0,0,0,0,0)`；面积 `(2,0,0,0,0,0,0)` |
| `Quantity` | 规范数值、量纲、工程量类型及绝对量/差量类别 | `1 m`、`0.5 m²` |
| `UnitDefinition` | 稳定 ID、符号、量纲、比例、偏移及允许的工程量类别 | `mm` 的比例为 `0.001` |
| `QuantitySpec` | 属性所需的量纲、工程量类型、类别和取值约束 | length 接收有限且大于零的长度 |
| `DisplayPolicy` | 显示单位、精度和样式 | 面积显示为 `mm²`，不参与模型运算 |

量纲相同也可能语义不同：能量和力矩都是 `M·L²·T⁻²`，需要额外的工程量类型区分。普通乘法只能推导量纲，未必能推导业务类型；语义有歧义时保留通用类型，由显式领域操作确认，不能按目标属性偷偷改类型。

本课程将角度的 SI 量纲记为无量纲，同时保留 `Angle` 类型。`Ratio` 和 `Angle` 不隐式互换，函数和赋值同时校验量纲与类型。`Quantity` 的构造经受检工厂完成，避免出现“长度量纲＋面积类型”这样的矛盾状态。

## 122. 内部应该保存毫米还是米，怎样与现有 CAD 模型协作？

本月拟议的独立工程量核心固定采用 **SI＋弧度**：长度用 m、面积用 m²、质量用 kg、时间用 s。内部约定是版本化契约，修改文档的显示单位不能修改它。选择 SI 便于与物理算法协作；代价是现有毫米接口需要适配。

现有文档与属性系统·第四月示例约定几何数值为 mm。两者之间设置明确边界：

| 边界操作 | 换算 |
|---|---|
| 输入 `1000 mm` → 工程量核心 | `1000 × 0.001 = 1 m` |
| 核心 `1 m` → 毫米坐标接口 | `1 × 1000 = 1000 mm` |
| 核心 `0.5 m²` → 旧面积接口 | `0.5 × 1000000 = 500000 mm²` |
| 旧长度容差 `0.01 mm` → 核心 | `0.00001 m` |

接口同时转换坐标、尺寸和相应量纲的容差。法向方向、比例、像素坐标各有自己的语义，不能给整个数据结构统一乘 `1000`。导入一次、导出一次；禁止调用方和被调用方重复换算。

对于已有生产系统，固定使用 mm 也能成立。本课选择 SI 是新设计的明确前提，不能据此直接重新解释旧文件中的裸数。

## 123. 单位注册表如何支持公英制、复合单位和偏移换算？

注册表将稳定单位 ID 映射为定义，符号及别名用于输入匹配。一般线性/仿射换算统一写为：

```text
规范值 = 输入值 × scale + offset
显示值 = (规范值 − offset) / scale
```

`mm` 的 scale 为 `0.001`，`in` 为 `0.0254`；二者 offset 都为零。面积和体积的比例由幂次产生：`mm²` 为 `10⁻⁶`，`mm³` 为 `10⁻⁹`。复合单位相乘时量纲指数相加、比例相乘，因此 `N/mm²` 对应 `10⁶ Pa`。

绝对摄氏温度的 scale 为 `1`、offset 为 `273.15`；温差 `delta_degC` 的 offset 为零。带偏移单位不能直接参加单位乘除或幂运算，`degC²` 应拒绝。温差单位可以组成 `delta_K/m`。

注册时检查比例有限且大于零、偏移有限、量纲指数范围以及符号冲突；内置定义不可被同名自定义单位覆盖。教学核心只支持整数指数；指数计算需检查溢出，分数次幂另行定义规则。

单位定义保存其来源和版本。像英寸这样的精确定义可记录有理比例 `127/5000 m`；数值求值仍采用浮点数，不能因为换算定义精确就声称浮点计算无误差。绑定后的单位定义不可原地修改；修改自定义单位创建新版本，已保存公式继续引用旧版本。

## 124. 工程量算术需要哪些规则，角度和温度有什么特殊性？

| 操作 | 校验与结果 |
|---|---|
| 长度＋长度、长度比较 | 先规范化，再校验兼容量纲及类型 |
| 长度×长度 | 指数相加，得到面积 |
| 长度÷长度 | 指数相减，得到普通比例；除数为零时报错 |
| 长度＋面积 | 拒绝，不能靠换算补救 |
| 角度×普通比例、角度÷普通比例 | 保留角度类型 |
| 角度÷角度 | 得到普通比例 |
| `sin(90 deg)` | 校验 Angle，转成弧度交给数学函数，结果为比例 1 |
| `sin(1)` | 拒绝；本课不把普通比例隐式当作弧度 |
| 绝对温度−绝对温度 | 得到温差：`20 degC − 10 degC = 10 delta_K` |
| 绝对温度＋温差 | 得到绝对温度：`20 degC + 10 delta_K = 30 degC` |
| 绝对温度＋绝对温度 | 拒绝；平均温度需定义专用操作 |

同类别温差可相加减；温差减绝对温度不成立。绝对温度直接乘除也不作为本课通用算术开放，热力学算法经受检接口取得 Kelvin 值。低于绝对零度的温度应由相应物理量约束拒绝。

类型规则必须随运算传播。尚未定义的特殊类型乘除返回“语义运算不支持”，不能悄悄丢掉 Angle 或温度类别。今后加入角速度等类型时，增加明确的推导规则。

## 125. 单位系统、FreeCAD、Boost.Units 与其他模块怎样分工？

| 模块 | 负责的决定 |
|---|---|
| 运行时工程量核心 | 值是什么、运算和换算是否合法 |
| 属性系统 | 目标接受什么类型和范围，统一校验与通知 |
| 表达式引擎 | 将文本变成运算结构，调用工程量规则 |
| 依赖图与重算器 | 哪些属性受影响、按什么顺序求值 |
| 参数化文档 | 事务、历史、配置、保存与加载 |
| UI/几何/算法适配层 | 格式化、坐标换算和外部类型转换 |

借鉴 FreeCAD 的运行时 `Quantity` 与显示方案分工；本课程设计不宣称复刻 FreeCAD 的全部规则。Boost.Units 适合保护预先确定类型的 C++ 算法接口，用户任意公式的类型则仍需运行时校验。

课程核心继续采用 C++23 标准库思路。Boost 是可选适配层：先检查量纲、工程语义与绝对量/差量类别，再换到目标基准单位，最后构造强类型；单独把 `double` 放进一个 Boost 类型无法证明输入正确。同量纲业务类型仍需领域封装，不能假定库会自动区分能量与力矩。
