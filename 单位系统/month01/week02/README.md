# 单位系统·第一月第 2 周：输入解析、显示与单位上下文

## 本周训练

- **承接与前置**：[上一周](../week01/README.md)已明确 Quantity、单位注册表和 SI 规范值；本周连接用户文本与核心。
- **目标**：说清楚无单位输入的含义、单位符号的解析、显示切换，以及编辑草稿所使用的上下文。
- **独立练习**：从 `length = 1 m`、`width = 0.5 m` 开始，文档默认输入/显示为 mm。在长度编辑框输入 `2 in`；再切到 cm 显示，最后在默认输入单位改成 cm 后输入 `3`。
- **验收**：两次提交分别保存 `0.0508 m` 和 `0.03 m`；中间显示为 `5.08 cm`，切换显示不改变模型数值。能解释为什么公式中的 `3` 仍是无量纲常量。

本周为独立的文本与数据推演，无需构建。工程量核心使用 SI＋弧度，属性编辑器和公式编辑器采用不同的裸数规则，以下例子均使用这一固定前提。

## 126. 如何从 `25mm`、`2.5 m` 和复合单位输入得到工程量？

解析依次完成数值识别、单位识别、单位表达式组合、受检换算；每一步保留原文位置。支持科学计数法时，`1e-3 m` 中的指数属于数字，不能被拆成属性名。

本月拟议语法将单单位数量写成 `25mm`、`25 mm`，复合单位写成 `2 [N/mm^2]`，括号内明确采用单位语法，普通公式乘除仍使用运算符。`mm²` 可规范化成 `mm^2`，但错误范围仍映射回原始文本。

```text
2 [N/mm^2]
  数字：2
  单位：N ÷ mm²
  量纲：M·L·T⁻² − 2L = M·L⁻¹·T⁻²
  比例：1 ÷ (0.001)² = 1000000
  结果：2000000 Pa
```

单位符号区分大小写，`m` 与 `M` 不能混用。优先识别已注册的完整符号，再按明确的前缀规则解析；禁止对整个文本做小写化。未识别的符号应报错，不能猜测用户意图。

裸标识符由公式语法解析为属性引用，数字后缀及方括号内的标识符解析为单位；两种命名空间分离。例如裸 `mm` 可以是属性名，而 `2 mm` 是数量常量。首期不支持任意隐式乘法，`2 length` 应要求改写为 `2 * length`。

英尺英寸和分数英寸属于额外输入格式，可先转成显式数量再进入核心。例如 `5 ft + 3 in` 等于 `1.6002 m`；未来接入 `5' 3"` 时，必须明确负号作用于整个长度，不能把它当作普通公式的引号语法。

## 127. 没有写单位的输入应该如何解释？

| 输入位置 | 裸数规则 | 示例 |
|---|---|---|
| 带类型的属性数值框 | 使用本次编辑捕获的有效输入单位 | 长度默认 mm，输入 `1000` 得到 `1 m` |
| 公式编辑框 | 数字恒为普通无量纲常量 | `length / 2` 合法；`length + 2` 不合法 |
| 外部 API | 量纲属性必须传带单位值或明确的规范量协议 | `{value: 1000, unit: "mm"}` |
| 普通比例属性 | 接收无量纲数值 | `ratio = 0.5` |

给公式中的所有数字自动补上目标单位，会把 `length / 2` 错误地解释成“长度除以长度”。本课因此规定公式 `width = 50` 不能写入长度属性，应写成 `width = 50 mm`；无量纲零也不例外。

属性数值框只对完整的裸数使用默认单位；复杂运算应进入公式入口，或使用专门规定的数量表达式入口。提交时立即将默认单位解析为确定的工程量，之后修改文档默认单位不能重新解释已提交数值。

## 128. 显示单位、显示精度和内部计算精度是什么关系？

格式化读取 Quantity 和显示策略，将规范值换成显示值，再做文本舍入。`1 m` 可以显示为 `1000 mm` 或 `39.3701 in`，模型值保持不变；保存和求值都不得读取舍入后的标签文本。

显示策略可包含固定小数位、有效数字或分数英寸。普通标签采用短格式，进入编辑时提供足够精度。若用户未修改文本就离开控件，不提交一次“舍入后的新值”；真正修改时才重新解析和校验。

模型的浮点数序列化采用足够的往返精度，例如 `max_digits10`，并固定机器格式的小数点。用户界面可以接受本地化小数分隔符，但持久化公式采用固定语言规则；转换本地化输入时须保留位置映射。

显示舍入与几何容差分别配置。显示 `0.00 mm` 并不证明尺寸为零；面积、长度、角度的误差阈值也不能共用一个裸 `epsilon`。

## 129. 应用、文档、属性和单次输入的单位配置如何协作？

显式输入单位优先于默认输入单位。裸数的默认输入单位依次取属性覆盖、文档输入方案；应用偏好只用于创建新文档的初值，不作为加载旧文档时的隐式全局依赖。显示单位独立地按属性覆盖、文档显示方案选择。

文档可以提供“输入单位跟随显示单位”的便利设置，但它只影响后续新编辑。每次开始编辑时捕获 `InputContext`：目标类型、有效输入单位、文档配置版本和区域格式规则。编辑过程中切换单位时保留并显示原上下文，或明确要求重新开始；不能在用户提交时偷偷改变解释。

例如以 mm 开始输入草稿 `20`，期间显示切到 in，该草稿提交仍是 `20 mm`。如果文档或目标属性已被替换，草稿应被清理或报告冲突，不能套用到另一个对象。

单位定义、单位配置和输入上下文各有生命周期：定义提供换算规则，配置选择规则，编辑上下文冻结一次输入的解释。计算模块不读取 UI 的当前下拉框。

## 130. 如何定位单位错误，并区分换算误差、显示舍入和几何容差？

结构化错误包含代码、阶段、原始文本范围、期望/实际量纲及目标属性键。词法层报告非法数字或符号，单位层报告未知单位，赋值层报告目标类型或范围不符。

| 输入/操作 | 应报告的原因 |
|---|---|
| 长度框输入 `2 kg` | 期望 Length，实际 Mass；标记单位片段 |
| 输入 `2 [mm^2]` 到 length | 期望长度量纲 L，实际 L² |
| 输入 `1e309 mm` | 数字或换算结果超出有限数范围 |
| 输入 `0 mm` 到正尺寸 | 单位正确，但违反大于零的属性约束 |
| 仅切换显示到 in | 显示刷新事件，不产生几何变更 |

UTF-8 字节范围需要在 Qt 适配层转换成 UTF-16 范围，特别是 `µ`、`²`、`℃` 等字符；不能直接把字节下标当作控件光标位置。

数值比较可采用 `|a−b| ≤ max(abs_tol, rel_tol × max(|a|, |b|))`，其中绝对容差与 a、b 同量纲，相对容差为比例。几何判断可以用这个规则，文档修改判定则比较规范内容；不能用几何容差吞掉真实用户编辑。除零检查使用明确的零判定，接近零的工程限制由算法另行规定。

单位不变性指物理意义不变，浮点往返按约定误差验收；显示切换则根本不回写数值，因此可以保证规范存储值保持原样。
