# 第3周讲义：带单位属性与表达式集成

## 本周训练

- **承接与前置**：[上周](../week02/README.md)已有数量解析和schema，复习AST、属性、依赖图及候选事务。
- **目标**：在App侧消费Quantity，分析三条写值通道，并让固定量纲的矩形属性参与公式和重算。
- **独立练习**：将width绑定为length/2+10mm、area绑定为length*width，修改length为2m；比较直接写值、脚本值和表达式值，再用ratio=0观察失败。
- **验收**：初始1000/510/510000，修改后2000/1010/2020000；两个派生属性各计算一次。脚本英寸输入归一化为38.1mm；非法公式不提交，合法除零进入Failed/Blocked并可恢复。

本周问题见[课程安排](../../课程安排.md#week03)，标准库ScriptValue只模拟输入形态，不嵌入Python。属性演示与文档模型的策略明确分开，依据见[参考校对](../../FreeCAD-Unit/README.md)。

## 131. PropertyQuantity为什么将内部数值、量纲和格式分别保存？

[property.cppm](property.cppm)将内部double、Unit和QuantityFormat分别持有，读取时组装Quantity。显示策略不改变值；Unit描述量纲，不保存“当前显示米还是毫米”。格式作为展示元数据，与数值运算及约束分离。

通用属性保留这种结构用于分析FreeCAD行为。文档Model的Property保存受检Quantity、QuantitySpec与公式状态，使用同一核心而不复制换算逻辑；两种结构是有意区分的教学接口。

## 132. 长度、面积、角度等具体属性如何声明默认量纲和取值约束？

具体属性选择默认Unit及范围，QuantitySpec保存可选上下界，范围不是量纲的一部分。矩形length/width/area下界为0，ratio无界，允许零值。

PropertyQuantityConstraint演示脚本通道裁剪和原始边界/步长读取。量纲相同不保证完整领域语义互斥：Work/Moment的Unit相等，压力/应力名称也不能替代业务检查。教学模型固定各属性Unit，不允许公式改变矩形长度的量纲。

## 133. C++、脚本与表达式写值通道的校验行为有哪些差异？

| 通道 | 通用属性的演示行为 |
|---|---|
| set_internal(double) | 输入已是内部数值，保留Unit；不裁剪，但教学实现仍拒绝非有限数 |
| set_script(ScriptValue) | double按当前Unit构造，字符串先解析，Quantity透传；有量纲时检查匹配，真正无量纲值保留属性Unit直接取数值 |
| set_expression(Quantity) | 非无量纲结果可更新通用属性Unit；保留输入内部值 |

`1.5 in`与长度属性相符，写入约38.1mm。数字1.5按当前量纲构造，字符串`"1.5"`才解析成无量纲。约束类只在脚本通道裁剪，其他通道不自动裁剪。演示记录可观察行为，不推断FreeCAD历史动机，也不把通用属性动态改量纲直接用于文档模型。

## 134. 数字、变量、运算符和函数表达式怎样携带及传播工程量？

[expression.cppm](expression.cppm)的节点记录Unit、常量或稳定PropertyKey。字面量在绑定时转换为毫米／度内部值，保留原文范围及稳定单位定义；属性引用从元数据取得Unit，即使当前值不可用也能先做量纲检查。

`length/2+10 mm`中2无量纲，长度除以比例仍是长度，再加内部值10。函数集中声明量纲和数值规则；sin/cos接受Angle或无量纲并按度转换，asin/atan2返回度。sqrt和常量分数幂必须产生整数指数；本教学表达式要求pow指数在绑定时确定，暂不实现动态幂。

公式支持显式加减乘除、括号和函数，复合量写`2 N/(1 mm*1 mm)`。第二周数量入口的`2 N/mm^2`不能直接当作本教学公式语法；同名入口并不保证完整语法兼容。[]注释不改变原文字节位置，公式原文仍完整保存。

一元负号属于内部运算，不作为negate函数开放；未知函数和参数数量错误返回诊断。

## 135. 表达式结果如何写回属性，量纲错误、约束处理和计算失败应在哪一层处理？

[document.cpp](document.cpp)在候选Model中修改、校验和拓扑重算，统一校验目标Unit和范围，成功才替换正式内容并发一次最终事件。常量范围错误、语法/引用/量纲/循环错误拒绝提交；不靠静默换量纲补救错误。

合法绑定的width=length/ratio在ratio改0后可执行失败：保留输入与历史，width标Failed、area标Blocked，value接口拒绝读取旧缓存。修复或撤销后按依赖顺序恢复，不把旧结果当成当前有效值。预览也实际计算派生结果，但不修改正式文档。显示配置只刷新格式，不重算；撤销重新推导必要结果，历史采用教学快照，不实现大型模型优化。

把公式替换成显式值会改变依赖关系，即使没有下游属性需要重算，也发布模型变化事件；撤销、重做沿用这一分类。

## 执行轨迹与运行

```text
length=1000 -> width=510 -> area=510000
length=2000 -> width=1010 -> area=2020000（各计算一次）
非法公式length+1kg -> 拒绝，无新增历史
ratio=0 -> width Failed -> area Blocked
ratio=4 -> width=250 -> area=250000（length恢复为1000后）
```

在本周目录执行：

```bash
./run.sh
cmake --preset default
cmake --build --preset default
ctest --preset default --no-tests=error
```
