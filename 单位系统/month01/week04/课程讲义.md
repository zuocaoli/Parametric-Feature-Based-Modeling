# 第4周讲义：应用装配、文档配置与完整生命周期

## 本周训练

- **承接与前置**：[上周](../week03/README.md)已将Quantity接入属性、公式和候选事务，本周装配服务与文档生命周期。
- **目标**：区分全局偏好、文档schema、属性覆盖与一次编辑上下文，完成保存加载。
- **独立练习**：保存1000/510/510000的矩形，将length输入2m再撤销，切换英寸并保存重开；创建两个不同schema文档，测试激活切换与旧草稿。
- **验收**：修改后2000/1010/2020000，撤销恢复1000/510/510000；显示39.3701in时内部仍1000、数值重算零次；重开后history=0、modified=false。

本周问题见[课程安排](../../课程安排.md#week04)。应用、文档、操作及存储均为本周完整源码，不依赖其他周；[FreeCAD参考](../../FreeCAD-Unit/README.md)用于职责和机制分析，本课程不是FreeCAD文件格式或脚本绑定的复刻。

## 136. 应用启动如何装配单位定义、单位制、偏好和统一服务入口？

[Application](application.cppm)拥有显式UnitsApi服务和UnitPreferences，负责新文档初值与当前文档激活。创建文档时复制偏好的schema及格式；后续改变偏好不会改写既有文档。服务实例随对象生命周期销毁，无全局单例或Python解释器。

FreeCAD由Application注册Python类型、读偏好并清理模块；本教学实现只保留职责结构。量纲与数量模块不依赖应用、文档或UI，schema服务不拥有事务和历史。

## 137. 全局偏好、文档单位制、属性显示覆盖与编辑上下文怎样协作？

文档保存UnitConfig.schema、输入/显示覆盖及精度；Application激活文档并决定有效schema。IgnoreProjectSchema启用时使用全局schema，属性显式覆盖仍优先；忽略配置只影响消费侧，不改写文档内容。全局单位覆盖仅作用于长度，其他量纲采用相应schema规则或属性覆盖。

`begin_edit`捕获文档identity、generation、PropertyKey、约束和已解析单位定义。普通长度裸数按schema的basic_length；“输入跟随显示”按当前值的实际显示规则冻结单位，复合单位也保存解析快照。长度的全局显示覆盖不会影响面积编辑。切换schema不能重解释旧草稿，换文档或加载替换后拒绝旧提交。上下文是瞬态对象，不持久化。

这是本项目的明确消费策略，不宣称FreeCAD存在相同的identity/generation接口。参数面板、完整本地化与多单位英寸输入不在本课程实现范围。

## 138. 单位输入和显示切换如何参与属性通知、依赖重算及命令事务？

[Operations](operations.cppm)提供强类型query/preview/apply，批次绑定expected_revision，共用候选事务。预览给出真实派生值；过期请求、非法公式或失败批次不覆盖正式文档。输入先转为Quantity，提交不再次读取当前显示单位。

数值修改标记下游并拓扑重算一次，显示/精度修改计算零次但发布格式事件。持久配置属于文档内容，可撤销并影响modified；历史位置、缓存和计算状态不参与未保存内容比较。合法修改引起Failed/Blocked仍可提交、保存、撤销或修复，陈旧结果不能当作有效值。

移除公式并写入显式值属于模型变化，不能根据重算列表为空判断为格式事件；撤销和重做同样发布模型变化。

## 139. 文档应保存哪些单位信息，加载和外部数据交换怎样避免重新解释裸数？

[storage.cpp](storage.cpp)保存当前课程模型：内部单位说明、八维Unit、规范输入与约束、公式原文及属性/单位绑定、自定义单位定义、schema及显示配置、元数据与对象ID。不保存依赖图、派生值和求值状态，加载时从权威数据重建。

内部单位明确为mm、kg、s、A、K、mol、cd、度。数字使用固定机器格式与max_digits10，不能用舍入显示文本代替规范值。文件上限1MiB、单类记录上限1024；错误的单位说明、坏绑定、缺失定义、非法约束、循环或尾随垃圾均拒绝加载。

加载先建立并检查候选模型，失败保留正式文档。保存先检查所有记录集合上限（含输入/显示覆盖、公式别名和单位绑定），再写同目录临时文件；写入和关闭成功后替换目标文件，再更新保存基准。超限失败保留原文件及保存基准。课程只提供这一套保存与加载入口。

几何交换使用显式单位的矩形记录，尺寸和线性容差一起换算，法向量不缩放。`1000 mm → 39.37007874 in → 1000 mm`按带量纲误差验收；没有STEP/IGES/BREP、OCCT或Boost依赖。

## 140. 怎样用完整矩形案例验证输入、表达式、重算、撤销、显示与保存的一致性？

| 操作 | 内部length/width/area | 预期 |
|---|---|---|
| 初始并保存 | 1000 / 510 / 510000 | modified=false |
| 输入2m | 2000 / 1010 / 2020000 | 一个历史项，两个派生属性各算一次 |
| 撤销 | 1000 / 510 / 510000 | 回到保存内容 |
| 选择ImperialDecimal | 数值保持 | length=39.3701in，重算零次，配置可撤销 |
| 保存并重开 | 数值、绑定、配置相同 | history=0，modified=false |
| 预览length=2000 | 正式值仍原样 | 候选area=2020000 |

另覆盖两个文档的偏好继承/激活/IgnoreProjectSchema、跨文档草稿拒绝、失败文件不替换、单位绑定恢复以及除零后状态恢复。存储往返比较权威输入和绑定；显示切换要求内部值原样；换算及求值用明确的绝对/相对误差。

## 运行与验收

在本周目录执行：

```bash
./run.sh
cmake --preset default
cmake --build --preset default
ctest --preset default --no-tests=error
./build/demo --save build/rectangle.cad
./build/demo --load build/rectangle.cad
```

[application_tests.cpp](application_tests.cpp)验证装配和编辑上下文，[operations_tests.cpp](operations_tests.cpp)验证批次与修订，[storage_tests.cpp](storage_tests.cpp)、[exchange_tests.cpp](exchange_tests.cpp)验证保存加载与单位交换；其余测试覆盖本周完整核心。构建/IDE/工具版本见[tools/README.md](tools/README.md)。

月底能够把一次输入从内部值跟踪到文档配置、保存和交换。[下一阶段](../../../几何引擎/month01/week01/README.md)使用毫米几何坐标并在度／弧度边界转换；大型尺度、容差与几何鲁棒性仍需专门学习。
