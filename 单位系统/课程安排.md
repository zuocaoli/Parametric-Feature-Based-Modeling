## 月目标与设计约定

能够解释从 `1.5 in` 输入到内部值、公式计算和单位制显示的完整路径，并说明各层的职责、接口边界与取舍。八维是CAD工程设计对七个SI基本量纲增加角度维度，不表示SI本身有八个基本量纲。

| 项目 | 新课程约定 |
|---|---|
| 量纲 | 长度、质量、时间、电流、温度、物质的量、发光强度、角度，按此顺序记录整数指数 |
| 内部单位 | mm、kg、s、A、K、mol、cd、度；面积为mm²、体积为mm³ |
| Unit | 表示量纲及其代数；相等比较指数，不把mm与in的符号差异视为量纲差异 |
| Quantity | 保存内部数值与Unit；输入单位的换算比例在解析时应用 |
| 单位制 | 通过规格表与策略选择显示单位和格式，不改变内部值 |
| App集成 | 属性声明量纲与约束，表达式传播工程量，应用装配服务，文档保存配置 |
| 外部边界 | 调用数学三角函数或需要弧度的几何接口时，显式将度转为弧度；数量输入语法与App公式入口分别说明 |

FreeCAD的量纲相同不等于业务含义完全相同，例如Work与Moment的指数相同；当前核心不保留额外Kind强类型。通用PropertyQuantity演示三通道差异，矩形文档采用固定Unit和范围的统一校验；不把源码中的动态改量纲直接作为模型策略，也不凭行为差异推断历史动机。

## 第1周：量纲代数与工程量核心

- **承接与前置**：前置课程已能保存矩形裸数和单位标签；本周先区分标签、量纲与真正参与计算的工程量。
- **目标**：理解Unit不依赖Quantity的底层边界，用指数向量解释算术，用固定内部单位解释数值。

| 题号 | 需要解决的问题 |
|---|---|
| 121 | 量纲、单位符号、工程量和显示文本分别是什么，为什么不能混用？ |
| 122 | FreeCAD为什么采用八维量纲，角度作为独立维度有什么作用？ |
| 123 | 怎样通过指数向量实现乘除、幂和开方，如何处理非法指数与越界？ |
| 124 | Quantity如何组合数值与量纲，为什么毫米加英寸合法、长度加面积非法？ |
| 125 | 采用毫米和度作为内部单位，会怎样影响力、压力及数学函数的换算？ |

**独立练习**：以length=`1000 mm`、width=`50 cm`建立矩形，记录两次输入的内部值、量纲和面积；再判断相加、相除及长度加面积。另列出 `1 N`、`1 Pa`、`90 deg` 与 `1 rad` 的内部表示，追踪90°进入数学函数的转换。

**验收**：内部长度为1000和500，面积为500000mm²，相加为1500mm，相除为无量纲2，长度加面积被拒绝。长度指数为 `(1,0,0,0,0,0,0,0)`，面积首项为2，角度仅末项为1。`1 N` 内部值为1000，`1 Pa` 为0.001，90°内部值为90，调用数学函数时为π/2弧度；`1 rad` 对应约57.2958°。平方根要求结果指数合法，例如面积开方得到长度，长度开平方不能悄悄截断指数。先独立推演量纲运算表和换算轨迹，再运行本周演示与测试核对。

**源码阅读**：从参考入口定位 `Base/Unit.h/.cpp` 的指数与相等规则、`Base/Quantity.cpp` 的换算常量。当前参照版本Unit指数范围为−8至7。

**下一周动机**：内部值有了稳定含义之后，需要解释同一个值为什么能按不同工程习惯显示，而不修改几何。

## 第2周：输入解析与数据驱动的单位制

- **承接与前置**：已有第1周的Unit、Quantity与固定内部值；本周连接用户文本和显示，不重新定义量纲算术。
- **目标**：区分解析、规范换算、格式化和单位制选择；理解数据表、单套schema、schema集合与门面的分工。

| 题号 | 需要解决的问题 |
|---|---|
| 126 | 数量解析器如何把数字、单位符号和复合单位转换为内部工程量？ |
| 127 | QuantityFormat如何控制精度和显示样式，为什么不能参与模型计算？ |
| 128 | UnitsSchemaSpec与换算规格表如何描述不同工程量的显示规则？ |
| 129 | UnitsSchema如何根据量纲类型、数值范围和规格表选择显示单位？ |
| 130 | UnitsSchemas与UnitsApi如何管理单位制集合、选择状态和统一调用入口？ |

**独立练习**：追踪 `25 mm`、`2 in`、`2 N/mm^2` 的解析，记录内部值和量纲。将同一个内部长度1000按MeterDecimal与ImperialDecimal显示；另设计“厘米教学制”的长度/面积规格表，只改数据，不复制格式化算法。补充一组自适应长度规则：绝对值小于1000时用mm，其他情况用m，并推演999、1000和−1000三个边界值。

**验收**：前三个内部值分别为25、50.8和2000，量纲为长度、长度和压力；压力显示为2000000Pa。内部长度1000显示为1m或约39.3701in，内部值始终为1000。厘米教学制的长度/面积factor分别为10和100，面积500000显示为5000cm²。边界三例显示为999mm、1m和−1m；输出规则表、解析/显示轨迹和失败诊断分类，运行本周演示；新增教学方案只改规格数据，复用已有翻译算法。

**源码阅读与取舍**：从 `Base/Quantity.l/.y` 读输入符号如何生成Quantity，再读QuantityFormat、UnitsSchemasSpecs/Data、UnitsSchema、UnitsSchemas及UnitsApi。普通显示值为内部值除以factor；未知类型可回退到量纲的内部单位字符串，默认阈值行负责覆盖剩余范围。数值阈值按绝对值选择，精确边界按所参照源码策略处理；其边界调整不是几何容差，也不参与文档是否修改的判定。分数英寸和多单位显示先理解专用格式分支，不要求在一周内复刻全部内置方案。

**语法边界**：本节参照FreeCAD数量入口，复合单位写 `2 N/mm^2`；方括号在该入口表示注释。`2 [N/mm^2]`在该数量入口表示无量纲2。数量输入与App表达式的函数入口也需分别说明，不能仅因名称相同就认定语义一致。

**下一周动机**：能够解析和显示工程量之后，需要让属性携带量纲，并追踪脚本、表达式和直接写值各自承担哪些校验。

## 第3周：带单位属性与表达式集成

- **承接与前置**：已有解析与显示策略；复习前置分类的属性元数据、AST与依赖图。本周在App层消费Quantity，不再写一套换算引擎。
- **目标**：解释属性内部数值、量纲和格式的分离，以及赋值入口、表达式运算和取值约束各自的检查位置。

| 题号 | 需要解决的问题 |
|---|---|
| 131 | PropertyQuantity为什么将内部数值、量纲和格式分别保存？ |
| 132 | 长度、面积、角度等具体属性如何声明默认量纲和取值约束？ |
| 133 | C++、脚本与表达式写值通道的校验行为有哪些差异？ |
| 134 | 数字、变量、运算符和函数表达式怎样携带及传播工程量？ |
| 135 | 表达式结果如何写回属性，量纲错误、约束处理和计算失败应在哪一层处理？ |

**独立练习**：将前两周固定width替换为 `width=length/2+10 mm`，再绑定 `area=length*width`。从长度输入1000mm出发，记录表达式节点中的值与量纲、属性写回和依赖顺序。另用通用PropertyQuantity绘制三通道行为表：C++直接写内部数值、脚本传数字/带单位字符串/真正无量纲Quantity、表达式传带量纲结果。补充约束类的越界脚本输入和表达式角度函数调用路径。

**验收**：width为510mm、area为510000mm²，面积节点读取本轮width的结果；`length+10 kg` 在运算时量纲不匹配。脚本 `1.5 in` 归一化为内部38.1，与长度量纲相符；浮点1.5按属性当前量纲构造，字符串 `"1.5"` 才可能走无量纲旁路。能指出表达式通道可将通用属性的Unit更新为结果量纲，这不是切换米／毫米显示，也不是“长度属性任意接收面积”的推荐策略。交付节点轨迹、通道对照表及错误归属表，不新增脚本绑定或解释器依赖。

**源码阅读与取舍**：阅读 `App/PropertyUnits.h/.cpp`、UnitExpression家族及PropertyExpressionEngine的写回入口。具体属性提供默认量纲和约束，不因此获得独立于量纲的完整领域类型系统；相同指数的工程名称不能保证互斥。量纲检查、业务范围和约束类脚本入口的裁剪是不同机制，不能把该入口的裁剪推断为所有通道的统一规则；长度默认下界0也不等于旧教学程序的严格大于0。

**函数边界**：当前参照版本的App表达式三角函数接受Angle或无量纲参数，按度转弧度后调用数学函数，反三角函数返回度。以 `sin(90 deg)=1` 推演边界，这不能推广为Base数量解析器所有同名函数的规则。保留“源码事实／教学建议／后续实现选择”三类说明，通用属性接口用于通道对照，矩形模型另行统一校验。

**下一周动机**：属性和公式已经能够消费工程量，还需要确定单位服务由谁创建、文档配置由谁激活，以及它们如何进入事务和保存流程。

## 第4周：应用装配、文档配置与完整生命周期

- **承接与前置**：已有第3周的属性和表达式消费路径；复习前置文档课程的命令、事务、通知与保存基准。
- **目标**：区分Base单位服务、App装配和文档职责，解释配置的存储、激活与消费，并以完整案例验证物理意义不变。

| 题号 | 需要解决的问题 |
|---|---|
| 136 | 应用启动如何装配单位定义、单位制、偏好和统一服务入口？ |
| 137 | 全局偏好、文档单位制、属性显示覆盖与编辑上下文怎样协作？ |
| 138 | 单位输入和显示切换如何参与属性通知、依赖重算及命令事务？ |

| 140 | 怎样用完整矩形案例验证输入、表达式、重算、撤销、显示与保存的一致性？ |

**独立练习**：以第三周矩形保存为基准，将length输入改为 `2 m`，记录内部值、公式执行顺序和文档变更；撤销后切换到米制或英制显示，保存并重新打开。另设计两份文档采用不同单位制时的激活流程，列出全局偏好、IgnoreProjectSchema、属性覆盖和未提交输入草稿的处理步骤。按内部单位契约、权威输入、公式绑定、显示配置和派生缓存分类制作保存/交换清单。

**验收**：修改后内部length/width/area为 `2000 mm / 1010 mm / 2020000 mm²`，撤销恢复 `1000 mm / 510 mm / 510000 mm²`。长度显示为1m或约39.3701in时，内部值仍为1000，显示切换不触发数值重算。能够分别指出：Application读取用户偏好并装配服务；Document存储UnitSystem；Gui在激活文档时消费配置，IgnoreProjectSchema影响方案选择。单位核心不负责命令历史、依赖调度、保存基准或文档生命周期。

**教学设计验收**：本项目实现中，持久配置有明确规则：持久显示配置的改动可撤销并参与未保存判断；保存重开后恢复权威值、公式和配置，再重建派生结果。输入开始时冻结目标和有效单位，切换显示不能重新解释旧草稿，文档或目标替换时拒绝旧提交。以上是本项目采用的教学设计，不宣称FreeCAD已有同样的InputContext、修订协议或文件格式。装配、事务和保存加载已在本周实现，交付装配职责表、完整状态轨迹与保存清单，并运行演示和测试核对。

**源码阅读与取舍**：从 `App/Application.cpp` 追踪偏好和单位服务的装配/清理，从 `App/Document.cpp` 读UnitSystem，再到 `Gui/Document.cpp`、`Gui/MainWindow.cpp` 及偏好页确认谁真正选择当前schema。属性覆盖和输入上下文需明确消费侧；不能只看到文档有枚举属性，就推断Base计算会自动读取文档配置。Python模块注册和清理用于理解生命周期，不要求课程引入Python运行时。

**月底成果与下一阶段**：能够串联输入、解析、量纲运算、schema显示、属性写回、依赖重算、事务和保存，并说明哪些是FreeCAD源码事实、哪些是本项目设计。后续进入[几何引擎第1周](../几何引擎/month01/week01/README.md)，毫米内部约定便于衔接，角度仍需在度／弧度边界显式转换；几何鲁棒性、尺度和容差不是单位正确即可自动解决的问题。

## 实现边界与源码对照

| 方面 | 当前教学实现 |
|---|---|
| 核心 | 独立Unit与Quantity模块，八维整数指数[-8,7]；同指数业务名称不构成额外强类型 |
| 内部数值 | mm/kg/s/A/K/mol/cd/度；m=1000、N=1000、Pa=0.001，数学边界转弧度 |
| 解析与显示 | 数量入口支持2 N/mm^2及[]注释；App公式使用显式数量乘除；schema表与格式化分离 |
| 单位制 | UnitsSchemaSpec、UnitsSchema、UnitsSchemas、显式实例UnitsApi；5个教学方案和按数据扩展示例 |
| App层 | 通用属性通道对照、固定量纲模型、候选预览/事务、依赖重算和应用/文档配置消费 |
| 持久化 | 保存当前模型的内部单位、权威输入、绑定与配置，加载时校验并重建计算结果 |

单位服务使用标准库实例，未复制FreeCAD的全局静态门面、完整单位清单、全部自适应显示、脚本绑定或GUI。分数英寸、多单位和完整本地化、偏移温度语义、第三方CAD文件格式仍为扩展内容。单位定义绑定、文档身份、冻结编辑与事务策略是本项目的教学接口，不宣称FreeCAD有相同协议。

## 独立运行与验收

在任意周目录执行：

```bash
./run.sh
ctest --preset default --no-tests=error
```

各周使用C++23、`import std;`、标准库及独立Clang+CMake+Ninja工程。分别注册2、4、7、11项CTest，工具版本与原生clangd步骤见本周tools/README.md；每周的课程讲义.md集中回答对应五题，并给出程序参数、预期结果与测试入口。第4周提供实际保存、加载及单位交换示例。
