# 第 4 周 · 重建失败与恢复

**承接** · 上周已能为受影响的特征安排增量重建。
**目标** · 跟踪两层失败，阻止下游消费过期结果，并在修正后恢复。

## 五个设计问题

1. **公式失败时谁先报告？** 表达式引擎将高度标为 `Failed` 并给出错误原因。拉伸缺少有效高度，切槽缺少有效底板，两者在特征报告中均为 `Blocked`，执行次数为零。
2. **有有效参数也会失败吗？** 会。公式求出的 `0 mm` 是有效数值，拉伸执行层会拒绝该高度，记录 `Failed` 和一次尝试，下游切槽仍为 `Blocked`。
3. **引用缺失如何记录？** 特征直接引用不存在的数值属性时记录 `MissingReference`，并把缺少的属性键写入诊断。依赖其实体的特征继续报告 `Blocked`。
4. **失败后如何查看旧几何？** `cached()` 提供最近一次成功的几何用于诊断。特征执行通过 `result()` 读取有效几何。
5. **恢复到原来的参数为何还要重建？** 失效到有效是一次状态变化。增量选择会重新安排底板及切槽，即使恢复后的高度与最近成功的高度相同。

## 练习与验收

运行 `./run.sh`，查看 `failure-recovery`。把公式换为 `2 * t / (segments - 1)`。令 `segments = 1` 触发除零，检查两个特征均为 `Blocked`。再把 `segments` 恢复到 2 且把 `t` 设为 `0 mm`，检查拉伸为 `Failed`、切槽为 `Blocked`。恢复 `t = 10 mm` 后，两者重新为 `Valid`，切槽体积为 `119000 mm³`。

独立练习在 [scenarios.cpp](scenarios.cpp) 中为额外拉伸传入一个不存在的属性键，并确认其报告为 `MissingReference`、执行次数为零。已有底板和切槽的有效结果应仍能读取。
