# 文档与属性系统

学习对象与属性、文档操作、界面适配和交付验证。完成本分类第一月后，先学习[表达式引擎与依赖图](../表达式引擎与依赖图/README.md)，再继续第二至四月。

## 第一月：对象与 Property 系统

第一月的目标：**理解 CAD 为什么需要对象和 Property 系统，并用纯 C++ 实现一个小型矩形参数模型。**

四周从普通矩形推进到统一属性、变更通知和对象管理。

| 周次 | 任务 | 需要解决的问题 |
|---|---|---|
| [第 1 周：普通对象](month01/week01/README.md) | 1 | 如何用一个 C++ 类表示具有长度、宽度和面积的矩形？ |
| | 2 | 矩形的面积应该存储为成员变量，还是每次调用时计算？ |
| | 3 | 如果长度和宽度是公开成员变量，外部代码可以随意修改，会产生哪些问题？ |
| | 4 | 如何通过统一的修改入口，保证矩形尺寸始终合法？ |
| | 5 | 如何判断一次赋值是否真正改变了尺寸？ |
| [第 2 周：属性抽象](month01/week02/README.md) | 6 | 如果不提前知道对象的具体类型，如何枚举它拥有的属性？ |
| | 7 | 一个属性除了数值，还需要保存哪些信息才能支持查看和编辑？ |
| | 8 | 如何用一套统一接口表示浮点数、整数、布尔值和字符串属性？ |
| | 9 | 如何通过属性名称查找属性，同时明确报告名称不存在的情况？ |
| | 10 | 通过统一接口修改属性时，如何保证类型和取值合法？ |
| [第 3 周：修改通知](month01/week03/README.md) | 11 | 属性修改成功后，如何让其他模块知道哪个对象的哪个属性发生了变化？ |
| | 12 | 修改通知应该在赋值之前还是之后发送？ |
| | 13 | 当两个模块都关心同一个属性时，如何让它们分别收到通知？ |
| | 14 | 一个订阅属性变化的模块销毁后，如何避免回调访问已经失效的对象？ |
| | 15 | 连续修改长度和宽度时，如何避免外部模块重复处理尚未完成的修改？ |
| [第 4 周：对象管理与整合](month01/week04/README.md) | 16 | 当系统中存在多个矩形时，如何为每个对象建立不随显示名称改变的身份标识？ |
| | 17 | 如何让一个文档统一负责矩形对象的创建、查找和销毁？ |
| | 18 | 当矩形对象被删除时，如何避免外部继续通过失效引用访问它？ |
| | 19 | 如何仅通过统一属性接口打印不同对象的数据，而不针对矩形编写特殊逻辑？ |
| | 20 | 如何用一个控制台示例证明对象管理、属性校验和修改通知能够正确协作？ |

月底成果：能管理多个矩形，统一校验与修改属性，并通知订阅者。

## 第二月：命令、事务与文档保存

目标：将参数化修改封装为命令，提供线性撤销/重做、一层组合事务、稳定对象身份恢复及多对象文档保存加载。

| 周次 | 任务 | 需要解决的问题 |
|---|---|---|
| [第 1 周：命令与历史](month02/week01/README.md) | 61 | 如何把一次属性修改封装成可以执行和撤销的命令？ |
| | 62 | 修改属性的命令需要记录哪些信息才能准确恢复旧状态？ |
| | 63 | 如何让不同类型的修改通过统一命令接口执行？ |
| | 64 | 如何管理历史记录，使撤销和重做按正确顺序执行？ |
| | 65 | 撤销后执行新的修改时，为什么需要丢弃原来的重做分支？ |
| [第 2 周：事务与失败恢复](month02/week02/README.md) | 66 | 如何让一次用户操作包含多个命令，并作为一个整体撤销？ |
| | 67 | 一组命令执行到中途失败时，如何恢复操作前的状态？ |
| | 68 | 如何让一组修改完成后只触发一次重算？ |
| | 69 | 用户直接修改的值和重算产生的值，分别应如何参与历史记录？ |
| | 70 | 如何区分“命令执行失败”和“命令成功但模型重算失败”，并制定对应的恢复规则？ |
| [第 3 周：模型生命周期](month02/week03/README.md) | 71 | 修改表达式的命令需要保存什么，才能在撤销时恢复公式与依赖关系？ |
| | 72 | 如何撤销对象创建，并在重做时恢复相同的对象 ID？ |
| | 73 | 如何撤销对象删除，同时恢复其属性和公式？ |
| | 74 | 删除对象导致其他公式引用失效时，如何在撤销删除后恢复计算链？ |
| | 75 | 命令长期保存在历史中时，如何避免它持有已经失效的对象指针？ |
| [第 4 周：保存与加载](month02/week04/README.md) | 76 | 为了完整恢复参数化文档，文件必须保存哪些数据？ |
| | 77 | 属性计算结果、依赖图和脏标记，哪些需要保存，哪些可以重建？ |
| | 78 | 如何分阶段加载对象、属性和公式，使引用不受文件记录顺序影响？ |
| | 79 | 如何在文件损坏或加载失败时，保留当前已经打开的文档？ |
| | 80 | 如何为文件设置格式版本，并明确处理不支持的版本？ |

四周独立构建，README 回答 61–80。事务成功后只重算并通知一次；失败操作保持模型与历史。合法修改造成计算失败仍可撤销，保存恢复这类模型时重建错误状态。文档采用 CAD_DOCUMENT 1 标准库文本格式，不持久化历史、图或公式结果。

第四周在 `文档与属性系统/month02/week04/build/document.txt` 保存两个矩形与跨对象公式，加载后修改来源对象，目标的 width/area 从 `10/1000` 更新到 `20/2000`；损坏或不支持版本的文件不会替换当前文档。

## 第三月：Qt6 QML 参数化编辑器

目标：让独立 C++ 核心通过 Qt 适配层驱动 QML 二维界面，完成选择、属性与公式编辑、错误反馈、拖动及文件保存加载。每周保留独立核心源码，控制台与 GUI 链接同一个纯 C++ 静态库。

| 周次 | 任务 | 需要解决的问题 |
|---|---|---|
| [第 1 周：模型与 QML 显示](month03/week01/README.md) | 81 | 如何让参数化核心作为独立库，被控制台程序和 QML 界面同时使用？ |
|  | 82 | 如何根据矩形的位置、长度和宽度生成二维显示图形？ |
|  | 83 | 如何将 QML 图形项与模型对象 ID 建立对应关系？ |
|  | 84 | 如何把模型中的坐标和长度映射到界面坐标及屏幕像素？ |
|  | 85 | 重算完成后，如何仅更新发生变化的对象图形？ |
| [第 2 周：选择与属性编辑](month03/week02/README.md) | 86 | 如何通过鼠标点击确定当前选中的模型对象？ |
|  | 87 | 如何让对象列表与画布共享同一份选择状态？ |
|  | 88 | 如何根据属性元数据生成适合不同类型的编辑控件？ |
|  | 89 | 如何让属性面板通过命令系统提交修改？ |
|  | 90 | 模型变化后，如何刷新属性面板而不再次触发修改命令？ |
| [第 3 周：公式与错误反馈](month03/week03/README.md) | 91 | 如何在属性面板中分别展示公式文本和计算结果？ |
|  | 92 | 公式驱动的属性应如何处理用户直接输入数值的操作？ |

|  | 99 | 删除选中对象后，如何清理选择状态和界面引用？ |
|  | 100 | 打开另一个文档后，如何解除旧文档订阅并重新建立图形与属性面板？ |

第一周显示模型，第二周开放选择和元数据属性编辑，第三周加入公式和撤销/重做，第四周开放拖动、删除和文件操作。模型坐标为毫米、X 向右、Y 向上；绑定公式的结果只读，先显式解除后才能改数值。磁盘使用 `CAD_DOCUMENT 2`，明确拒绝旧格式。

界面运行需要 Qt6 图形环境，自动 UI 测试可使用 offscreen；依赖见各周 tools/README.md。

构建后可按各周说明运行 UI 测试。每周产物在该周目录的 build/ 下（如 文档与属性系统/month03/weekXX/build/），包括 demo、console-demo、ui-tests、libcad_core.a 与生成的 Qt 元对象/资源文件。界面验收及截图命令见[第四周](month03/week04/README.md)。
