# CAD/CAE 表达式引擎设计之一 · 从公式文本到语法树

做 CAD/CAE 研发，我关心一条公式如何成为模型的一部分。用户输入 `length / 2`，系统需要识别它、读取参数、计算结果，再让受影响的尺寸得到更新。这里同时涉及语言处理、模型数据和更新调度。

我用一个参数化矩形贯穿这个系列。长度是输入，宽度和面积由公式驱动。

```text
width = length / 2
area  = length * width
```

这里的等号表示属性与公式的绑定关系。解析器实际接收的是等号右侧的表达式文本。

## 先看模块如何协作

从一次公式编辑到结果更新，数据依次经过以下模块。

| 模块 | 主要职责 | 核心数据结构 |
|---|---|---|
| 词法分析 | 把字符识别为数字、变量、运算符和括号 | `Token`、`vector<Token>` |
| 语法分析 | 按优先级组织计算结构 | `Node`、`Tree` |
| 名称解析与求值 | 找到变量对应的属性，执行算术运算 | `Resolver`、`Value` |
| 公式绑定 | 维护目标属性与公式定义 | `Binding`、绑定表 |
| 依赖管理 | 记录属性之间的引用关系，检测环并排序 | `PropertyKey`、双向邻接表 |
| 重算调度 | 收集受影响公式，合并修改并安排执行 | 脏集合、批次深度 |
| 状态与生命周期管理 | 传播失败，处理删除、修复和保存恢复 | 状态表、执行报告、模型快照 |

语言前端生成的抽象语法树（AST）同时服务于求值和依赖提取。属性系统负责保存数值、校验修改和发送通知。重算协调器把这些模块装配成自动重算流程。

## Token 要保留足够的诊断信息

对于 `length / 2 + 5`，词法分析得到变量、除号、数字、加号、数字和结束标记。用 C++ 表示时，Token 可以包含类别、原文、起始位置和数字值四个字段。

```cpp
// 词法单元的类别，供解析器识别数字、变量、运算符和括号。
enum class TokenKind {
    Number,     // 数字字面量，例如 12、.5、2.。
    Identifier, // 变量名，例如 length、width。
    Plus,       // 加号 +，也用于一元正号。
    Minus,      // 减号 -，也用于一元负号。
    Star,       // 乘号 *。
    Slash,      // 除号 /。
    LeftParen,  // 左括号 (。
    RightParen, // 右括号 )。
    End         // 输入结束标记，位置为输入文本长度。
};

// 词法分析得到的一个单元，保留原文与位置供后续诊断使用。
struct Token {
    TokenKind kind;       // 当前单元的类别。
    std::string text;     // 原始文本的副本，例如 "length"、"2"。
    std::size_t position; // 在输入文本中的起始字节位置，从 0 开始。
    double number = 0.0;  // 数字单元转换后的值，其他类别不使用此字段。
};
```

`kind` 供解析器判断类别，`text` 保留原文，`position` 指向起始字节，`number` 保存已经转换的数字。显式的 `End` 标记让解析器可以检查整段输入是否处理完毕。

Token 自己持有文本，AST 的生命周期因而可以超过调用者传入的字符串。复制文本增加了一些内存开销，也简化了绑定长期保存语法树时的所有权管理。

这里采用一组基础词法规则。数字接受整数和小数，包括 `.5` 和 `2.`，扫描结束后使用 `from_chars` 转换，并检查转换范围与有限性。负号独立成 Token，后续语法分析再确定它表示一元取负还是二元减法。标识符由 ASCII 字母、下划线和数字组成，数字只能出现在首字符之后。

## AST 把优先级写进结构

表达式 `length / 2 + 5` 可以用下面的结构表示。

```text
Binary(+)
├── Binary(/)
│   ├── Variable(length)
│   └── Number(2)
└── Number(5)
```

求值时沿树递归，除法自然先于加法执行。依赖提取时遍历变量节点，就能收集到 `length`。

四则运算可以用四种节点类型表示，分别对应数字、变量、一元运算和二元运算。

```cpp
enum class NodeKind {
    Number,   // 数字字面量，例如 2，无子节点。
    Variable, // 变量引用，例如 length，无子节点。
    Unary,    // 一元运算，例如 -length，操作数放在 left。
    Binary    // 二元运算，例如 length + 2，使用左右两个子节点。
};

// 一个 AST 节点，保存节点类型、对应 Token 和子树。
struct Node {
    NodeKind kind;               // 当前节点表示哪一种表达式。
    Token token;                 // 对应的词法单元，保留文本、位置和数字值。
    std::unique_ptr<Node> left;  // 左子节点，也保存一元运算的唯一操作数。
    std::unique_ptr<Node> right; // 右子节点，由二元运算使用。
    std::size_t height = 1;      // 当前子树的高度，叶子节点为 1。
};

// 独占持有 AST 根节点，销毁时递归释放整棵树。
using Tree = std::unique_ptr<Node>;
```

一元运算把唯一操作数放在 `left`，二元运算使用两个子节点。每个节点只有一个父节点，`unique_ptr` 表达这种所有权，解析中途失败时也会释放已经构造的子树。

统一节点结构让遍历逻辑直接，构造函数与求值器共同检查节点形态。`height` 则记录子树高度，供解析阶段限制递归规模。

## 递归下降对应四层语法

这个表达式语言只有四则运算、括号和一元正负号，递归下降可以直接映射它的语法。

```text
additive       → multiplicative { ('+' | '-') multiplicative }
multiplicative → unary { ('*' | '/') unary }
unary          → ('+' | '-') unary | primary
primary        → number | identifier | '(' additive ')'
```

低优先级函数调用高优先级函数，形成优先级层次。同级运算通过循环不断把已有子树接到新节点左侧，因此 `length / 2 / 5` 被解析为 `(length / 2) / 5`。一元运算递归调用自身，支持 `--length` 这样的嵌套。

加减层可以写成下面的伪代码，`current` 表示当前 Token，`advance()` 取出它并移动游标。

```text
function parse_additive():
    tree = parse_multiplicative()
    while current.kind is Plus or Minus:
        operator = advance()
        right = parse_multiplicative()
        tree = Binary(operator, tree, right)
    return tree
```

循环每执行一次，就把之前的整棵树接到新运算符左侧。左结合规则由这个构树过程直接保证。

括号通过再次进入加减层处理，树中保留其分组结果。解析结束后要求当前位置为 `End`，因此 `length 2` 这样的尾随输入会被报告。

我会同时限制括号及一元运算的递归嵌套，以及最终 AST 的高度。例如可以将两项上限设为 128，再根据实际运行栈空间调整。长加法链即使通过循环解析，也会形成较深的左子树，树高检查覆盖了这种情况。

## 错误位置需要一路保留

非法字符属于词法错误，缺少操作数或右括号属于语法错误。错误需要包含阶段、字节位置和原因，才能由参数编辑器给出具体反馈。下面的 C++23 接口通过 `std::expected` 返回语法树或错误。

```cpp
enum class ErrorStage {
    Lexical,    // 词法错误，字符或数字字面量无法组成合法 Token。
    Syntax,     // 语法错误，Token 顺序不符合表达式语法。
    Evaluation, // 求值错误，例如变量不可用、除零或非有限结果。
    Binding,    // 绑定错误，目标属性不符合要求或结果写回失败。
    Storage     // 存储错误，模型保存或加载失败。
};

struct Error {
    ErrorStage stage;     // 错误发生的处理阶段。
    std::size_t position; // 错误在输入文本中的字节位置，从 0 开始。
    std::string message;  // 具体原因，供参数编辑器显示。
};

// 将表达式文本解析为 AST，成功返回 Tree，失败返回 Error。
std::expected<Tree, Error> parse(std::string_view source);
```

递归解析过程中，任一子表达式失败都会向调用方传播。内部可以逐层返回错误，也可以用局部异常退出递归，再在公开入口转换为 `expected`。

对于 CAD 参数编辑器，这些信息可以用于定位公式中需要修改的位置。当前位置按字节记录，接入 Unicode 编辑控件时还需要转换为控件使用的字符坐标。

我会把 AST 作为后续模块共同消费的表达式表示。求值读取它，依赖分析遍历它，绑定持有它，诊断则利用节点上保留的 Token 定位问题。
