# CAD/CAE 表达式引擎设计之二 · 求值与属性绑定

在参数化模型中，`length / 2` 的含义依赖于它所在的对象、引用的属性以及目标尺寸的约束。设计这一层时，我会分别考虑表达式如何读取数据、如何执行，以及结果如何进入模型。

继续使用矩形案例，输入 `length=100`，为 `width` 绑定 `length / 2`，再为 `area` 绑定 `length * width`。

## 用 Resolver 接入属性系统

我用 `Resolver` 回调为求值器提供变量查询能力。下面的 C++23 接口中，`Node` 表示语法树节点，`Error` 携带错误阶段、位置和原因。

```cpp
// 属性值在任一时刻保存实数、整数、布尔或字符串中的一种。
using Value = std::variant<double, std::int64_t, bool, std::string>;

// 根据变量名查询属性值，无法提供值时返回 std::nullopt。
using Resolver = std::function<std::optional<Value>(std::string_view)>;

// 执行已解析的 AST，成功返回数值，失败返回包含原因和位置的错误。
std::expected<double, Error>
evaluate(const Node &node, const Resolver &resolve = {});
```

遇到变量节点时，求值器把名字交给 `Resolver`，得到属性值或空结果。矩形属性的查找、对象定位和有效状态检查，由装配回调的上层完成。

这样，求值模块只依赖属性值类型与查询契约。接入其他领域对象时，可以提供相同形式的读取回调。单独验证算术行为时，也可以用一个简单变量表作为数据来源。

## 属性类型与算术规则分别定义

这个属性容器能保存实数、整数、布尔和字符串。为了建立基本的算术语义，我让求值器接受 `double`，并将 `int64_t` 转为 `double`，布尔和字符串参与算术会返回错误。结果统一为 `double`，公式目标也限定为可写的实数属性。

这种规则足以表达尺寸和整数计数之间的运算。大整数转成 `double` 时可能损失精度，因此若后续需要精确的整数公式，就需要扩展求值结果类型与运算规则。

求值过程递归执行四类节点，每次得到数值后检查 `isfinite`。除法对分母做精确零判断，覆盖正零和负零。尺寸的工程容差可以在领域规则中定义，除法本身按浮点算术处理非零分母。

下面用伪代码表示求值流程。`require` 表示取得成功结果，遇到错误就向调用方返回。`numeric()` 检查变量是否存在、类型是否为数字，转换后再检查有限性。`finite()` 检查运算结果是否为有限数。

```text
function evaluate(node, resolve):
    if node.kind == Number:
        return finite(node.number)
    if node.kind == Variable:
        return numeric(resolve(node.name))

    left = require evaluate(node.left, resolve)
    if node.kind == Unary:
        return finite(apply_unary(node.operator, left))

    right = require evaluate(node.right, resolve)
    if node.operator == '/' and right == 0:
        return error(node.position, "division by zero")
    return finite(apply_binary(node.operator, left, right))
```

`apply_unary()` 执行正负号，`apply_binary()` 执行四则运算。示例将节点上的数字、变量名和运算符直接展开，实际数据结构可以通过节点保存的 Token 取得它们。

## 计算成功后还需要属性校验

表达式 `-length` 可以成功算出 `-100`。如果目标是矩形宽度，属性校验仍会拒绝它，因为这里要求矩形长宽为有限正数。

我把属性的单项修改入口记为 `set()`，多项修改入口记为 `set_many()`。单项修改复用多项修改的流程，检查属性存在性、只读状态、类型与取值，全部通过后才提交变化并通知订阅者。公式结果通过这个属性层入口写回，沿用手动输入的模型约束。

`set_many()` 先收集全部待修改项，确认合法后统一交换存储值，最后发送一次包含所有实际变化的 `ChangeEvent`。订阅者读取同一对象时，已经能看到该次修改的完整结果。

## 绑定保存公式定义，属性保存计算值

一条绑定需要保存公式原文、AST 和变量映射。下面的结构同时给出了属性定位方式，`Tree` 表示独占持有的 AST。

```cpp
// 用对象身份和稳定属性名定位一个属性。
struct PropertyKey {
    std::uint64_t object; // 所属对象的稳定 ID。
    std::string name;    // 对象内的稳定属性名，例如 "width"。

    // 按 object、name 依次比较，供有序容器查找和排序。
    auto operator<=>(const PropertyKey &) const = default;
};

// 公式中的变量名映射到具体属性，支持跨对象引用。
using VariableMap = std::map<std::string, PropertyKey, std::less<>>;

struct Binding {
    std::string source;  // 公式原文，例如 "length * width"。
    Tree tree;           // 已解析的 AST，后续重算直接复用。
    VariableMap aliases; // 变量名到具体对象属性的映射。
};

// 每个目标属性最多绑定一条公式，计算结果保存在目标属性中。
std::map<PropertyKey, Binding> bindings_;
```

`source` 用于展示、编辑和保存，`tree` 供后续直接执行，`aliases` 指明变量到具体属性的映射。计算结果仍然保存在目标对象的属性中，每个目标最多对应一条绑定。

这使修改输入时可以复用 AST。计算失败时，模型还可以保留最近一次成功写入的数值，同时由状态表表达当前结果是否有效。引擎对外的输入修改接口会拒绝直接赋值给公式目标，用户可以编辑公式或解除绑定。引擎内部的结果写回经过属性层的校验入口。

## 公式编辑要有明确的提交边界

对已有公式进行替换，我会按下面的顺序处理。

1. 确认目标存在、可写且为实数属性。
2. 解析新公式，构造候选 AST。
3. 提取变量并解析成属性键，检查引用存在且类型可用于算术。
4. 在候选依赖图上替换关系，检测循环。
5. 提交绑定与图，把目标及下游标脏，进入重算。

语法错误、无效引用和循环会在提交前返回，已有公式、依赖关系、属性缓存和计算状态得以保留。提交阶段应同时发布新绑定与新图，让后续调度看到一致的定义。

运行期错误则有另一条处理路径。例如 `length / (segments - 1)` 在 `segments=1` 时仍然可以完成绑定，随后的求值进入 `Failed`。用户可以继续修改输入，修复已提交公式的计算条件。编辑器可以通过绑定返回值判断定义是否被接受，再通过状态与重算报告展示执行结果。

## 量纲与领域约束各有位置

属性元数据可以用 `unit` 字段记录展示单位，上面的求值示例则执行标量运算。若要支持 `2 mm + 4 m`，需要让值表示携带量纲，并在运算规则中完成兼容检查和单位换算。

我会将这项能力接入值类型和求值语义，同时继续由属性校验约束几何尺寸、材料参数等领域取值。这样，算术合法性、量纲合法性和目标属性合法性都有对应的处理位置。
