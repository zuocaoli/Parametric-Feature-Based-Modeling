# CAD/CAE 表达式引擎设计之三 · 属性依赖图的设计

当用户修改一个尺寸，表达式引擎需要回答两个问题。哪些公式受影响？这些公式按什么顺序计算？我用属性级有向无环图（DAG）描述这些依赖。

以参数化矩形为例，长度是输入，宽度由 `length / 2` 得到，面积由 `length * width` 得到。长度更新后，宽度和面积都需要重算，且面积需要等宽度更新后再读它。

## 图节点使用对象 ID 与属性键

我把节点定在属性粒度。同一个矩形里，修改 `name` 和修改 `length` 的含义不同。按对象记录依赖时，两种修改会命中同一个节点。细化到属性后，一条只读取 `length` 的公式可以忽略对 `name` 的修改，同一对象内部的 `length → width` 也有了明确的表达。

手动输入和公式目标都使用同一种节点。公式属于目标属性的绑定，节点仍然代表这个属性。给 `width` 绑定或解除公式，都可以沿用原来的属性键，已经引用它的公式也能继续读取这个键。

属性键由对象 ID 和稳定属性名组成，并支持比较，以便作为有序容器的键。

```cpp
// 用对象身份和稳定属性名定位一个属性。
struct PropertyKey {
    std::uint64_t object; // 所属对象的稳定 ID。
    std::string name;    // 对象内的稳定属性名，例如 "width"。

    // 按 object、name 依次比较，供有序容器查找和排序。
    auto operator<=>(const PropertyKey &) const = default;
};

// 属性键的有序集合，用于去重依赖或记录待处理目标。
using KeySet = std::set<PropertyKey>;

// 公式中的变量名映射到具体属性，支持跨对象引用。
using VariableMap = std::map<std::string, PropertyKey, std::less<>>;
```

对象 ID 确定身份，属性键定位对象内部的数据。界面中的对象名称与标签可以独立展示，图中的引用沿用稳定身份。

名称解析先查 `VariableMap`，找到时使用显式映射，否则按公式所属对象的属性名解析。假设对象 A 的 ID 为 1，对象 B 的公式为 `source_segments + 1`，可以给它附上一张别名表。

```text
source_segments → PropertyKey{1, "segments"}
```

公式中的 `source_segments` 由此指向 A 的 `segments`。这种设计通过别名表提供跨对象引用，表达式词法仍使用普通标识符。

## 每条边记录一次直接依赖

对于 `length * length + width`，遍历所有变量节点可以得到变量集合 `{length, width}`。同一变量在计算中出现两次，在依赖图中只需登记一次。

依赖提取可以分两步去重。先用 `set<string>` 收集变量名，再将每个名字解析为 `PropertyKey`，放入 `KeySet`。如果两个别名最终指向同一属性，第二步仍能合并。

依赖提取与求值使用同一份别名映射，确保图上登记的属性就是运行时读取的属性。AST 记录一条公式内部的运算结构，DAG 则将多条公式的直接引用组织成属性间的关系。

统一约定边的方向为“输入属性 → 使用它的目标属性”。矩形案例包含三条边。

```text
length → width
length → area
width  → area
```

这里要保留 `length → area` 这条直接边，即使已经存在 `length → width → area` 的路径。假设宽度改绑为常量 `80`，`length → width` 会被移除，面积公式仍然直接读取 `length`。如果先前只保留间接路径，这次编辑就会让长度变化漏掉面积重算。图应忠实记录每条公式的直接输入，传递关系在查询下游时再计算。

## 一张图保存两个查询方向

依赖图维护两份邻接索引。

```cpp
// 目标直接依赖哪些属性，例如 parents_[area] = {length, width}。
std::map<PropertyKey, KeySet> parents_;

// 哪些目标直接使用该属性，例如 children_[length] = {width, area}。
std::map<PropertyKey, KeySet> children_;
```

| 查询 | 矩形中的结果 | 使用场景 |
|---|---|---|
| `parents_[area]` | `{length, width}` | 计算前检查输入、统计入度 |
| `children_[length]` | `{width, area}` | 参数修改后沿下游传播 |

两份索引增加了边的存储量，也让两类查询可以直接定位邻接集合。维护时需要保证两个方向完全对应，`source` 属于 `parents_[target]`，当且仅当 `target` 属于 `children_[source]`。

公式替换时，先从旧输入的下游集合中移除目标，再写入新的前置集合并登记对应下游。解除公式时清空该目标的前置关系，同时保留其他公式对它的引用。绑定常量公式也会得到空前置集合，目标究竟由常量公式驱动还是由用户赋值，由绑定表决定。

下面的伪代码只描述关系维护，缺失的邻接集合按空集合处理。调用方会在候选图上执行它，完成无环检查后再提交。

```text
function replace_dependencies(target, new_parents):
    // 从旧输入的反向索引中移除目标。
    for source in parents[target]:
        children[source].remove(target)

    // 更新目标的直接输入，并登记每个新输入的下游。
    parents[target] = copy(new_parents)
    for source in new_parents:
        children[source].insert(target)
```

## 拓扑排序处理汇聚依赖

这里使用 Kahn 算法。先统计每个节点的入度，把入度为零的节点放进就绪集合。每取出一个节点，就减少其下游的剩余入度，下游减到零时进入就绪集合。

把 `length` 从 100 改为 200 后，先沿 `children` 收集下游，得到 `{width, area}`。面积经两条路径到达，集合里只登记一次。随后将这个集合交给 `topological_order(selected)`。长度已提交，无需参加本轮排序，因此宽度的本轮入度为 0，面积的本轮入度为 1。

按这个顺序，宽度先更新为 100，面积随后算出 20000。如果先算面积，它会读取上次的宽度 50，得到 10000。拓扑排序确定先后，协调器还要检查所有直接输入的有效状态，包括本轮集合之外的输入。

```text
function topological_order(selected):
    indegree = empty map
    ready = empty ordered set
    order = empty list

    // 只统计本轮也要处理的前置属性。
    for target in selected:
        indegree[target] = size(parents[target] intersect selected)
        if indegree[target] == 0:
            ready.insert(target)

    while ready is not empty:
        source = ready.remove_first()
        order.append(source)
        for target in children[source] intersect selected:
            indegree[target] -= 1
            if indegree[target] == 0:
                ready.insert(target)

    if size(order) < size(selected):
        return error("dependency cycle", find_cycle(selected))
    return order
```

这里的 `intersect` 表示集合交集。选中的每条内部依赖边都会影响目标入度，汇聚节点要等所有前置节点处理完成后才会就绪。

就绪集合采用 `set`，使多个合法顺序之间的选择保持确定。底层使用有序容器，实际运行成本还包含查找和插入的对数开销。

## 公式提交时保证图无环

已有 `width=length/2`，再绑定 `length=width*2`，就会形成 `length → width → length`。两条公式彼此等待，无法通过一次顺序求值完成更新。CAD 中需要联立求解的关系，应交给约束求解器处理。

拓扑排序通过“输出节点数少于选中节点数”判断存在循环。随后用三色 DFS 搜索具体路径，颜色分别表示未访问、位于当前递归路径和已经完成。遇到当前路径中的节点时，截取闭合部分，并在末尾追加起点。

错误因此可以携带 `vector<PropertyKey>`，供界面定位相关尺寸。

提交新公式前，先在候选图上替换目标的直接依赖，再检查整张图是否无环。通过后一起提交公式绑定和依赖图，失败时用户能看到具体环路，原公式和原图仍可用于计算。

复制图和全图检查的成本随模型规模增长。如果公式编辑成为性能瓶颈，可以缩小检查范围。在已知原图无环的前提下，先移除被替换的旧边。每次准备加入 `source → target` 时，检查 `target` 能否沿下游到达 `source`，把自引用视为长度为零的可达路径。逐条对更新中的候选图检查，才能发现多条新增边共同形成的环。
