# CAD/CAE 表达式引擎设计之五 · 错误恢复与模型生命周期

在 CAD/CAE 模型中，用户会暂时输入无法计算的公式，也会删除其他参数正在引用的对象。我关心系统在这些编辑过程中如何表达结果是否可用，以及修复操作如何重新打通计算链。

我会为属性维护有效状态，通过受控读取把结果交给下游，并用稳定的对象身份处理引用的生命周期。

## 属性需要同时记录数值与有效状态

对象 A 的宽度绑定 `length / (segments - 1)`，面积绑定 `length * width`。当 `segments` 从 2 变为 1，输入自身仍满足正整数校验，宽度公式却会除零。

此时可以保留宽度和面积之前的缓存数值，并通过独立状态表记录当前可用性。

| 状态 | 含义 |
|---|---|
| `Valid` | 当前结果有效，可以交给调用者 |
| `Dirty` | 已受变化影响，等待重新计算 |
| `Failed` | 已尝试求值，求值失败或写回被拒绝 |
| `Blocked` | 直接输入处于无效状态，当前目标等待修复 |
| `MissingReference` | 直接引用的对象或属性已经缺失 |

状态保存为 `PropertyStatus {state, reason}`，由对象 ID 与属性名组成的 `PropertyKey` 索引。把缓存读取记为 `stored_value()`，把提供有效结果的读取记为 `value()`，后者在状态为 `Valid` 时才返回数值。

```text
function value(key):
    if key does not identify an existing property:
        return unavailable
    if status[key].state != Valid:
        return unavailable
    return stored_value(key)
```

界面可以通过缓存读取展示历史数值与错误提示，后续计算通过受控读取获取可用结果。

## 按依赖关系隔离失败

每个目标执行前，协调器先检查直接输入。引用缺失时进入 `MissingReference`，引用存在但状态无效时进入 `Blocked`，条件满足后才执行 AST。

单个目标的处理可以写成下面的伪代码。`finish()` 记录状态、原因与执行次数，`parents[target]` 表示该目标的全部直接输入。

```text
function process(target):
    inputs = parents[target]
    if any input property is missing:
        return finish(target, MissingReference, executions=0)
    if any input status is not Valid:
        return finish(target, Blocked, executions=0)

    result = evaluate(binding[target].tree, resolve_valid_input)
    if result is an error:
        return finish(target, Failed, executions=1)

    assigned = property_set(target, result.value)
    if assigned is Changed or Unchanged:
        return finish(target, Valid, executions=1)
    return finish(target, Failed, executions=1)
```

`resolve_valid_input` 按绑定中的变量映射定位属性，再调用 `value()` 读取。`property_set()` 经过属性校验后提交结果，求值或校验失败时保留旧缓存。

在上面的除零场景中，A 的宽度为 `Failed`，执行次数为 1，A 的面积为 `Blocked`，执行次数为 0。若对象 B 的宽度只依赖 A 的 `segments`，其输入仍然有效，这条分支可以继续成功计算。

执行循环会逐项记录结果，单个目标失败后继续处理其他目标。用户因此能够看到出错参数及其下游，同时继续使用有效分支。

## 修复由相关变化重新启动

把 `segments` 从 1 改为 3，宽度和面积重新进入 `Dirty`，再按拓扑顺序执行。长度为 100 时，恢复后的宽度为 50，面积为 5000。

修复绑定同样会标记目标与下游，常量公式也会主动标记目标本身。成功写回返回 `Changed` 或 `Unchanged`，都会恢复为 `Valid`。

这套调度策略在每轮结束时清除处理过的脏任务。失败状态由状态表保留，相关输入真正变化或绑定被修复时，再产生新的重算任务。界面可据此围绕错误原因引导修改。

## 删除对象前先收集影响

对象删除需要先利用完整依赖图确定下游，再按以下顺序处理。

1. 遍历对象属性，把所有受影响的下游目标标脏。
2. 移除对象自身的公式、待办任务、状态和订阅，再删除对象。
3. 保留其他对象公式指向旧属性键的引用关系。
4. 执行受影响目标，将直接使用者标为 `MissingReference`，其下游标为 `Blocked`。

保留旧属性键让错误仍然指向原来的依赖身份。对象 ID 单调分配，新建对象获得新 ID，通过显式修改别名映射并重新绑定，用户可以确认新的数据来源。

解绑公式则清除目标对上游的依赖，保留它的当前数值与下游引用，并将其恢复为普通输入，再安排下游更新。

## 通知订阅也参与生命周期管理

引擎可以把领域对象与它的变化订阅连接存入同一条管理记录。连接采用可移动、独占退订责任的 RAII 对象，析构时断开订阅。

发布者持有订阅状态的强引用，连接持有弱引用。发布者先销毁时，连接仍可安全析构。发送通知时复制订阅列表快照，逐项检查有效状态，并捕获回调异常，继续通知其他订阅者。

这使对象删除、订阅断开和同步回调遍历有明确的所有权规则。

## 保存恢复需要保留设计定义

保存模型时，需要记录稳定对象身份、属性类型和值、公式原文，以及跨对象引用的映射。下面用精简 JSON 示意一条公式的保存内容，`target` 指向对象 2 的宽度，别名映射到对象 1 的长度。

```json
{
  "target": {"object": 2, "property": "width"},
  "source": "source_length / 2",
  "aliases": {
    "source_length": {"object": 1, "property": "length"}
  }
}
```

模型文件还需要保存对象 1 和对象 2 的定义与输入属性。AST 可以由原文重建，依赖图可以由 AST 和别名映射重建，计算状态则在加载后的校验与重算中重新确认。最近成功结果可以作为缓存保存，供加载过程中的界面展示。

加载顺序需要考虑跨对象引用。我会先创建所有对象并恢复稳定 ID，再通过属性校验恢复输入值，随后解析全部公式、恢复引用、检查整张图，最后统一重算。多条公式可以在这一阶段一起完成准备，等引用关系齐全后再发布模型。

```text
function load_model(snapshot):
    model = create_all_objects(snapshot.objects)
    restore_and_validate_inputs(model, snapshot.values)
    bindings = parse_and_resolve_all(model, snapshot.formulas)
    graph = build_and_validate_graph(bindings)
    model.install(bindings, graph)
    model.mark_all_formula_targets_dirty()
    model.recompute()
    return model
```

对象定义、输入、公式解析和图校验中的错误会中止加载，并返回具体原因。通过这些检查后，重算中的求值失败按前述状态规则记录，以便用户打开模型后修复公式。

数值序列化还需要保证往返精度。使用 C++ 文本流时，可以固定经典 locale，并以 `max_digits10` 输出浮点数。字符串则由格式对应的转义规则处理，确保公式中的字符能完整恢复。

面向更完整的 CAD/CAE 平台，可以沿现有职责继续增加能力。

| 能力 | 主要设计落点 |

| 单位与量纲 | 值表示、运算规则、单位换算 |

我会围绕公式定义、属性身份、依赖关系、结果状态和执行时机审视这些扩展。各模块保持清晰的输入输出，才能把语言能力与模型生命周期逐步装配起来。
