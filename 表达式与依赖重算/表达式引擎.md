# CAD 中的表达式引擎：能力全景

> **一句话概括**：表达式引擎是参数化 CAD 的"计算中枢"——它把模型中所有数值输入
> （尺寸、角度、个数、位置等）从"写死的常量"升级为"可引用、可计算、可联动的变量与公式"，
> 是参数化建模、关联设计、变型设计和知识工程得以成立的底层支撑。

---

## 1. 参数化驱动：让模型"由变量算出来"

- 几乎任何属性都可以绑定表达式，而不只是尺寸——拉伸长度、圆角半径、阵列个数、
  角度偏移，甚至"引用哪一个草图"都可以由公式决定。
- 典型例子：`矩形宽度 = 2.5 × 高度`、`拉伸长度 = 高度 / 2`，
  设计规则直接写进模型，而不是靠人工换算后逐个填数。
- 通过**全局变量**建立命名的"设计接口"：用变量驱动尺寸、
  用尺寸和变量再定义新变量，形成参数网络。

## 2. 设计意图的固化与自动关联更新

- 修改一个参数，所有依赖它的尺寸和特征**自动重算**，
  这是参数化设计区别于直接建模的核心。
- 引擎在背后维护**依赖关系图（DAG）**：

  ```text
  解析表达式引用 → 登记依赖 → 拓扑排序 → 增量求值 → 触发几何重建
  ```

- 同时进行**循环依赖检测**，防止"A 驱动 B、B 又驱动 A"的死锁。
- **架构意义**：表达式引擎把"参数逻辑层"与"几何内核层"解耦——
  引擎只负责算出正确的参数值，几何内核负责据此重建模型，两者各自可独立演进。

## 3. 单位与量纲感知（工程语义的正确性保障）

- 运算符和函数是"单位感知"的：
  - `2mm + 4mm` ✅ 合法
  - `2mm + 4` ❌ 非法（纯数不能与带单位的量相加）
  - `2mm + 4m` ✅ 自动换算
- 支持大量单位关键字，并可通过运算组合出新单位（如 `m/s`），
  保证工程计算不会"数值对了、量纲错了"。

## 4. 完整的计算语义：函数、条件逻辑、多种数据类型

- 支持数学/三角函数、比较运算，以及三元条件表达式：

  ```text
  condition ? 结果A : 结果B
  ```

  让模型能按条件切换形态（如"长度 > 100 时加强筋，否则不加"）。
- 表达式值不限于实数，可支持**数字、字符串、布尔、整数、点、矢量、列表**
  等类型，驱动更丰富的几何定义。

## 5. 跨对象 / 跨零件 / 跨文档引用 → 自顶向下设计

- 引用文档内任意对象的属性（如 `Cylinder.Height`）、
  草图约束（如 `Constraints[16]`）。
- 支持**跨文档链接**，如 `master#modelConstants.Length`，
  用一个主控文档的参数驱动多个从动零件。
- 装配级关联的典型用法：
  - **部件间表达式**：让"轴的外径始终等于孔的内径"；
  - 在装配体中提炼全局变量，再向下关联子零件尺寸。

## 6. 外部数据驱动与系列化变型设计

- 表达式可直接引用**电子表格**单元格或单元格别名（如 `Spreadsheet.Height`），
  把参数集中管理在表格里。
- 配合**配置表**：一行定义一个规格（Small / Mid / Large…），
  用户在下拉框切换变型，整个模型自动变形——
  标准件、系列化产品由此实现"一套模型、多种规格"。
- 进一步扩展为**零件级可变、模块级可组合、整机级可配置**的全链路参数化复用。

## 7. 知识工程（KBE）与测量反哺

- 工程规范、经验公式以表达式形式沉淀进模型，成为可复用的设计知识
  （关系式、公式/知识工程模块都属同类机制）。
- 模型自身的测量结果（体积、重量、子装配宽度等）也能通过表达式
  反向输出到表格做汇总报表，形成**"参数驱动几何、几何反哺数据"**的闭环。

## 8. 自动化、优化与二次开发的手柄

- 命名参数天然成为 API、脚本和设计算例（Design Study）可操纵的变量入口，
  是做尺寸优化、敏感性分析的前提。
- 创成式设计/拓扑优化也建立在参数化建模之上：
  定义并操作设计参数，才能自动批量生成设计备选方案。

## 9. 工程健壮性与可用性

- 引用对象标签时用 `<<Label>>` 语法，对象重命名后表达式自动跟随更新，
  不会"改名即断链"。
- 编辑器提供**自动补全**和**实时求值预览**，输入公式时立刻看到结果，
  降低出错成本。

## 主流 CAD 中的对应机制

| 软件         | 表达式引擎的外在形态                            |
| ------------ | ----------------------------------------------- |
| SolidWorks   | 方程式 + 全局变量 + 设计表                      |
| Siemens NX   | 表达式（多类型）+ 部件间表达式                  |
| FreeCAD      | Expression Engine + Spreadsheet/VarSet + 配置表 |
| PTC Creo     | 关系式（Relations）                             |
| CATIA        | 公式（Formula）+ 知识工程模块                   |

---

## 总结

没有表达式引擎，CAD 只是一个"电子图板"；有了它，CAD 才成为一个
**可计算、可关联、可配置、可编程的设计平台**：

- 设计意图被编码为公式；
- 修改被依赖图自动传播；
- 变型被数据表批量驱动；
- 知识被沉淀复用。

这正是参数化 CAD 相对于直接建模的本质竞争力所在。
